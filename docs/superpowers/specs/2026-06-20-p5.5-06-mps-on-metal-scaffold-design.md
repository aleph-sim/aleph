# P5.5-06 — MPS-on-Metal scaffold (start) — Design

> Issue: #176 `[P5.5-06] MPS-on-Metal scaffold (start)`
> Depends on: P5.5-03 (FP32 Metal SV core), P5.5-05 (#196, FP32 oracle + bench infra).
> Status: design 2026-06-20.

## Goal

Stand up the **first Metal MPS backend** — `MetalMpsBackend` — as a *scaffold*: a
correct-but-minimal GPU MPS that runs nearest-neighbour (NN) circuits with the
hot per-gate tensor work on the GPU and the SVD on the CPU. It is a "start", not a
performance artifact (Phase-5.5 perf is owned by the SV path, P5.5-05).

### Acceptance criteria (from #176)

- [ ] NN circuits run on `MetalMpsBackend`; the dense statevector matches the CPU
  MPS backend (`aleph_mps::MpsBackend`) within `1e-5`.
- [ ] The CPU-SVD round-trip cost is documented.

## Scope decisions

**1. Where it lives — `aleph-metal`, new `src/mps/` module (sibling of `src/sv/`).**
Mirrors `MetalSvBackend`'s home and reuses the existing public Metal infra
(`MetalContext`, `DeviceBuffer<T>`, `make_compute_pipeline`, the `include_str!`
shader pattern) with zero new plumbing. Gated behind the existing `metal` feature,
so Linux/headless builds stay empty-crate.

**2. Minimal "naive" MPS, not canonical-form.** The CPU MPS
(`aleph-mps`) maintains an orthogonality centre for *numerically optimal*
truncation. For a correctness scaffold on modest circuits we do **not** need it:
every NN 2q gate does contract → apply → thin-SVD → split, absorbing the singular
values into the right tensor. This represents the exact state (up to truncation)
and is far less code than porting the canonicalisation machinery. We run the
oracle with a bond cap high enough that small Tier-1 NN circuits incur **no**
truncation, so the result equals the exact statevector to fp32 precision.

**3. NN 2q only.** The issue specifies "NN 2q". Non-adjacent 2q gates return
`BackendError::UnsupportedInstruction` (no SWAP router in the scaffold). The CPU
MPS's lazy-SWAP routing is deferred to a later issue. Test circuits are NN by
construction (GHZ CNOT-chain, NN brickwall).

**4. SVD on CPU via `faer`, exploiting unified memory.** `DeviceBuffer<T>` is
`StorageModeShared`, so its `as_slice()` is a zero-copy host window onto GPU
memory. After the gate-apply kernel's `wait_until_completed`, the host reads the
Θ′ buffer **directly** — there is no explicit device→host copy. The real "round-trip
cost" is therefore (a) the GPU pipeline barrier and (b) the CPU running a
single-threaded LAPACK-class SVD while the GPU sits idle, then the host writing the
two split tensors back into fresh shared buffers. This is what we measure and
document (AC #2), and it is the honest reason a unified-memory MPS-on-Metal cannot
yet beat CPU MPS — exactly the kind of structural note Phase 5.5 wants.

## Architecture

### State — `MetalMpsState`

```
struct SiteTensor { left: usize, right: usize, buf: DeviceBuffer<Complex<f32>> }   // (left,2,right), row-major data[(l*2+p)*right + r]
struct MetalMpsState { num_qubits: u32, sites: Vec<SiteTensor> }
```

Initialised as the product state |0…0⟩: each site `(1,2,1)` with `data = [1+0i, 0+0i]`.
Because the scaffold is NN-only, site order ≡ qubit order throughout (no permutation
bookkeeping). `HasAmplitudes` is implemented via a host dense contraction
(`amplitudes() -> Vec<Complex<f64>>`), used only by the oracle.

### GPU kernels (new `.metal` shaders, runtime-compiled like the SV ones)

1. **`apply_1q_site`** — in-place 2×2 on a site's physical index. Grid =
   `left·right`; each thread updates the `p=0` / `p=1` pair at fixed `(l,r)`.
   No SVD, no bond change (mirrors `MpsState::apply_1q`).
2. **`contract_2site`** — `A(la,2,c) · B(c,2,rb) → Θ` as a row-major matrix of
   shape `(la·2) × (2·rb)` with `Θ[la_i*2+p][p'*rb+rb_j] = Σ_c A[(la_i*2+p)*c+c'] · B[(c'*2+p')*rb+rb_j]`.
   Grid = one thread per output element (`la·2·2·rb`); each sums over the shared
   bond `c`.
3. **`apply_2q_theta`** — in place on Θ: `Θ'[la_i,(ap,bp),rb_j] = Σ_{(a,b)} U[(ap<<1|bp)][(a<<1|b)] · Θ[la_i,(a,b),rb_j]`,
   with `qa` the MSB and `qb` the LSB (matching the CPU MPS convention
   `out(p_msb,p_lsb)=(p_msb<<1)|p_lsb`). Grid = one thread per `(la_i, rb_j)`;
   each gathers its 4 entries, applies the 4×4, scatters back. The 4×4 complex
   matrix is uploaded into the existing `mat_scratch`-style buffer.

### CPU host step (per NN 2q gate)

After `apply_2q_theta` + barrier: read Θ′ via `as_slice()`, widen f32→`aleph_core::Complex`
(c64), thin-SVD with `faer` (`Θ′ = U·diag(σ)·Vᴴ`), pick `χ` and a renorm `scale`
via a ported `svd_truncation_plan`, then write back:
- `A_new (la,2,χ)` ← `U[:, :χ]`,
- `B_new (χ,2,rb)` ← `diag(σ_scaled)·Vᴴ` rows `0..χ` (S absorbed right),
into two fresh `DeviceBuffer<Complex<f32>>`. SVD runs in f64 for accuracy; only the
stored tensors are f32.

### Backend trait

`impl Backend for MetalMpsBackend` with `type State = MetalMpsState`:
`allocate`, `apply_gate` (1q → kernel 1; NN 2q → contract+apply+SVD; non-NN →
`UnsupportedInstruction`), and `measure`/`sample`/`expectation_value`/`probabilities`
either delegated to a host dense path or returning `UnsupportedInstruction` for the
scaffold (the oracle only needs `run` + amplitudes). `run`/`run_optimized` wrap
`aleph_backend::{run, run_optimized}` like the SV backend. Constructors `new()` /
`with_seed(u64)` follow the device-or-skip idiom (`Err` when no Metal device).

## Reuse (from the architecture map)

- `MetalContext::{new, make_compute_pipeline}`, `DeviceBuffer::{from_slice, as_slice, metal_buffer}`,
  `include_str!` shaders, `set_buffer`/`set_bytes`/`dispatch_threads`/`wait_until_completed`
  — all already public/`pub(crate)` and used by the SV backend.
- `svd_truncation_plan` (≈30 lines) is ported verbatim into the mps module
  (it is `pub(crate)` in `aleph-mps`, so cannot be imported across the crate
  boundary); `faer` thin-SVD via the high-level solver (`Svd::new_thin`), since the
  per-call-`Par` micro-optimisation is irrelevant to the scaffold.
- `aleph_core::Complex == faer::c64`, so host SVD needs no element-type juggling.

## Testing & verification

- `cargo test -p aleph-metal --features metal --test mps_oracle` (Mini) — NN GHZ +
  NN brickwall, dense SV vs CPU MPS within 1e-5, plus a 1q-only sanity case.
- A correctness-at-scale guard is unnecessary here (the oracle *is* a full
  exact-vs-MPS compare); the bond cap is set so the small test circuits never
  truncate, making the comparison exact-to-fp32.
- `cargo test --workspace` / clippy `--all-targets -D warnings` / fmt — green
  off-feature (the module is `#[cfg(feature="metal")]`).
- `cargo clippy -p aleph-metal --features metal --tests -- -D warnings` (P5.5-04
  lesson: lint under the feature).

## Out of scope / non-goals

- No canonical-form / orthogonality-centre engine (naive split each gate).
- No SWAP routing → no non-NN 2q gates.
- No GPU SVD (faer on host; the documented round-trip).
- No perf gate — correctness + documented cost only. Measurement/perf verdict for
  the MPS path rolls up in P5.5-07.
