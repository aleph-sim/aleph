# P5.5-04 — Fused-block (UnitaryKq) GPU run path, correctness, and benchmark

Date: 2026-06-17
Issue: [P5.5-04] Fused-block (UnitaryKq) GPU kernel (#174)
Depends on: P5.5-03 (#173, merged `07b8f79`)

## Background

P5.5-03 already shipped the substance the issue title names: a unified `apply_kq`
Metal kernel that routes `Gate::UnitaryKq` (k = 2–5), `M4×4`, and `M8×8` gates, and
`apply_gate` dispatches `UnitaryKq` to it directly. Independently, `FuseKq` is already
the second-to-last pass in `PassPipeline::default_pipeline()`. Therefore the generic
`aleph_backend::run_optimized` — which clones the circuit, runs the default pipeline,
executes, and settles the qubit permutation via `unpermute_state` — already feeds fused
dense blocks to the GPU kernel today.

What is *not* yet done, and what this ticket delivers:

1. An ergonomic optimized-run entry point on `MetalSvBackend` (the "full optimized run
   path on the backend").
2. The AC's explicit correctness proof: the fused path matches the unfused path within
   `1e-5` on the GPU.
3. The AC's criterion benchmark: fused faster than unfused on ≥1 Tier-1 workload.
4. A short perf note recording the measured ratios.

No new kernel code is required.

## Acceptance criteria (from the issue)

- [ ] Fused-block kernel matches unfused within 1e-5.
- [ ] Criterion: fused faster than unfused on ≥1 Tier-1 workload (M4 base).

## Hardware note

The reference hardware in the AC is "M4 base". No M4 is available locally; the dev box is
an **Apple M3** (MacBook Air, 8-core, 4P+4E). All measurements in this ticket are taken on
the M3 and the perf note flags the delta explicitly. The fused-vs-unfused *direction*
(fewer GPU round-trips ⇒ faster) is hardware-agnostic; only absolute ratios differ.

## Design

### 1. Optimized run path on `MetalSvBackend`

Add two thin, documented methods to `impl MetalSvBackend` (in `src/sv/backend.rs`). They
wrap the existing generic free functions — no execution logic is duplicated.

```rust
impl MetalSvBackend {
    /// Execute `circuit` gate-by-gate (unfused) on the GPU, returning the
    /// device-resident final state. Thin wrapper over `aleph_backend::run`.
    pub fn run(&mut self, circuit: &Circuit) -> Result<MetalSvState, BackendError>;

    /// Optimize `circuit` with the default pass pipeline (cancellation, DCE,
    /// 1q/2q/kq fusion) and execute it on the GPU. The fused dense blocks ride
    /// the `apply_kq` kernel; any qubit permutation introduced by the pipeline
    /// is settled via `unpermute_state`, so the returned state is in logical
    /// qubit order — directly comparable to `run`. Thin wrapper over
    /// `aleph_backend::run_optimized`.
    pub fn run_optimized(&mut self, circuit: &Circuit) -> Result<MetalSvState, BackendError>;
}
```

`Circuit` is `aleph_ir::Circuit`. `aleph-backend` and `aleph-ir` are already optional deps
of the crate under the `metal` feature, so no new dependency is added for this section.

Rationale: callers (and the new tests/bench) get one entry point instead of hand-wiring
`aleph_backend::run_optimized(self, circuit)` and reasoning about whether a permutation
needs settling. Readout (`sample`/`measure`/`expectation_value`/`probabilities`) then
operates on the returned `MetalSvState`.

### 2. Correctness — fused == unfused within 1e-5 (AC #1)

New on-device unit tests in `backend.rs`'s `mod tests`, using the existing
`backend_or_skip()` device-or-skip pattern so headless CI passes.

For each Tier-1 workload — GHZ, QFT, random brickwall, Grover — at a small `n` (≈ 6–8,
keeping them fast and within the established oracle range):

1. Build the circuit.
2. `unfused = backend.run(&c)` then read `amplitudes_f32()`.
3. `fused = backend.run_optimized(&c)` then read `amplitudes_f32()`.
4. Assert equal length and amplitude-by-amplitude agreement: for every index `i`,
   `(fused[i] - unfused[i]).norm() < 1e-5`.

This is the literal AC #1 ("fused-block kernel matches unfused within 1e-5"), expressed as
GPU self-consistency. It complements — does not replace — P5.5-03's fused-Metal-vs-CPU
oracle (`tests/sv_oracle.rs`), which pins absolute correctness against the f64 reference.

Circuit sources (reused, no reimplementation):
- GHZ / QFT / random: `aleph_benches::{ghz_circuit, qft_circuit, random_brickwall_circuit}`.
- Grover: parse a small QASM fixture via `aleph_parser::parse`
  (`scripts/qiskit-baseline/circuits/grover_n4_iters3.qasm` for the test's small `n`).

`aleph-benches` and `aleph-parser` are added as `[dev-dependencies]` (test + bench only).

A guard is needed: the random-brickwall builder uses a fixed seed so the circuit is
deterministic across the two runs — confirm the builder is seed-stable (it is; it takes no
RNG handle and builds a fixed structure) or pin the seed at the call site.

### 3. Benchmark — fused faster than unfused (AC #2)

New file `crates/aleph-metal/benches/sv_fused.rs`, `harness = false`, registered in
`Cargo.toml` with `required-features = ["metal"]` so `cargo bench --workspace` and Linux
builds skip it (the crate is an empty compile without `metal`). Run explicitly on the Mac:

```
cargo bench -p aleph-metal --features metal --bench sv_fused
```

Structure: one criterion group per workload, each with two benchmarks, `unfused` and
`fused`:

```
for &n in BENCH_QUBITS {            // ≈ 14–18, per workload
    let circuit = build(workload, n);            // built once, outside iter
    group.bench("unfused", || run_with_setup(MetalSvBackend::with_seed(0), |b| b.run(&circuit)));
    group.bench("fused",   || run_with_setup(MetalSvBackend::with_seed(0), |b| b.run_optimized(&circuit)));
}
```

Backend is rebuilt per iteration via `iter_with_setup` (pipeline compile is one-time and
cheap relative to the measured run, but a fresh backend keeps the zero-state allocation out
of the steady-state timing — matching the CPU benches' `with_seed` setup idiom). The
circuit and any parsed Grover source are built once outside the timing loop.

Workloads and sizes:
- QFT: n ∈ {14, 16, 18} — canonical fusion beneficiary (H + cphase ladder).
- random brickwall: n ∈ {14, 16, 18}, fixed depth — dense 2q gates fuse into `UnitaryKq`.
- GHZ: n ∈ {16, 18} — light fusion; reported honestly (may not win).
- Grover: a mid-size QASM fixture (e.g. `grover_n15_iters5.qasm`) — heavier, one point.

If a device is absent the bench cannot run; criterion benches assume the dev Mac has a GPU.

The AC requires fused to beat unfused on **≥1** workload; QFT and random are expected to
win clearly because the per-gate `wait_until_completed` makes GPU round-trip count the
dominant cost, and fusion cuts the gate count substantially. GHZ/Grover results are
reported as-measured.

Dev-deps added to `aleph-metal/Cargo.toml`: `criterion`, `aleph-benches`, `aleph-parser`.
(`aleph-backend`/`aleph-ir`/`aleph-core` are reachable through the `metal` feature, which
the bench requires.)

## Out of scope

- Batched command buffers / removing the per-gate `wait_until_completed`. This is the
  obvious next perf lever (flagged in the P5.5-03 retro) and the path to the P5.5-05 ≥2×
  exit gate, but it is a separate optimization with its own correctness surface. P5.5-04
  only needs to demonstrate that fusion (fewer dispatches) already helps.
- Any new kernel or shader code.
- M4 measurement (no hardware).

## Testing summary

- Unit (on-device, device-or-skip): fused == unfused within 1e-5 for GHZ, QFT, random,
  Grover at small n.
- Existing P5.5-03 oracle (`tests/sv_oracle.rs`) and proptest (`tests/sv_proptest.rs`)
  continue to gate absolute correctness; unchanged.
- `cargo clippy --workspace --all-targets -- -D warnings` and `cargo fmt --check` green.
- Criterion bench produces fused-vs-unfused numbers on the M3 (manual, non-gating —
  feature-gated bench, and the self-hosted Linux bench runner has no Metal).

## Risks / notes

- **f32 self-consistency tolerance.** Both paths are f32 on the same kernel; differences
  come only from fewer/larger matmuls in the fused path. 1e-5 at small n is comfortable;
  if a workload grazes it, the test n can drop further (the AC tolerance is fixed at 1e-5).
- **Grover via QASM.** Reuses the existing baseline corpus; if a chosen fixture exceeds the
  28-qubit Metal cap or the small-n test budget, pick a smaller `grover_nN` file.
- **`required-features` bench is skipped by `cargo bench --workspace`** (documented in
  CLAUDE.md). That is intended — Metal benches are macOS-only and run explicitly.
