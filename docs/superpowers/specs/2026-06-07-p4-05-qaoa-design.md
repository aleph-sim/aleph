# P4-05 — QAOA benchmark, Max-Cut on small graphs (design)

**Issue:** #43 (`area:bench`, `type:test`, `priority:critical`, Phase 4, est. L)
**Depends on:** P1-14. Builds heavily on P4-04 (`aleph-py`, `PauliSum`,
`expectation_pauli_sum`, the Python-driver pattern).
**Date:** 2026-06-07

## Goal

A QAOA Max-Cut benchmark on seeded 3-regular graphs of 6/10/14 nodes at depth
p=1/2/3, driven from Python through `aleph-py`. Delivers: (1) approximation
ratios within 0.9× of the exact optimum at p=3 for the small graphs, and (2) an
energy-evaluation timing comparison **across backends** — aleph state-vector,
aleph MPS, and Qiskit Aer — in a dedicated `docs/perf/qaoa.md`.

Single combined ticket building on the P4-04 `aleph-py` foundation.

## Acceptance criteria (from BACKLOG)

- [ ] QAOA produces approximations within 0.9× optimal for small graphs →
  Python `qaoa.py --ratio` (COBYLA, p=3, n=6/10) + the committed ratio table.
- [ ] Benchmark across backends → `qaoa.py --bench` times aleph SV, aleph MPS,
  and Qiskit Aer → `docs/perf/qaoa.md`.
- [ ] Time scaling report → `docs/perf/qaoa.md` (n×p timing).
- Sanity: p=1 gives the expected approximation ratio → reported, and the Rust CI
  gate asserts the deterministic p=1 grid optimum.

## Locked design decisions

- **Optimizer:** SciPy COBYLA (`scipy.optimize.minimize`, scipy 1.17 in venv),
  with a few random restarts (QAOA landscapes have local optima). Rotosolve
  (P4-04) does NOT apply — the cost-layer γ landscape is multi-harmonic.
- **Graphs:** seeded **3-regular** random graphs (networkx 3.6, in venv) for
  n=6/10/14 (all even). Committed as edge-list data + exact brute-force max-cut.
- **Backends:** aleph SV (`NaiveSvBackend`) + aleph MPS (`MpsBackend`) + Qiskit
  Aer (`save_expectation_value`). All single-thread.
- **Approximation ratio:** assert ≥0.9 at p=3 for n=6 and n=10; report all
  (n,p) ratios honestly. n=14 reported without a hard 0.9 gate (disclosed if it
  falls short). No cherry-picking seeds.
- **Report:** dedicated `docs/perf/qaoa.md` (QAOA's n×p×backend shape doesn't fit
  `phase4.md`). `report.py`/`phase4.md` untouched.
- **No n=20 stretch point.** Stick to the backlog's 6/10/14.

## Architecture — five layers

### 1. `aleph-ir::ansatz`: QAOA circuit + Max-Cut Hamiltonian
- `pub fn build_qaoa(n_qubits, edges: &[(u32,u32)], gammas: &[f64], betas: &[f64])
  -> Result<Circuit, AnsatzError>`:
  - `H` on every qubit (uniform superposition).
  - For each layer `l` in `0..p` (where `p = gammas.len()`, must equal
    `betas.len()`): **cost** — for each edge `(i,j)`: `CNOT(i,j); Rz(2*γ_l, j);
    CNOT(i,j)` (the `RZZ(2γ_l)` decomposition); **mixer** — `Rx(2*β_l, q)` on
    every qubit. (The existing `bench_fixtures::qaoa` fixture is linear-chain
    only and feature-gated; `build_qaoa` is graph-aware and always-public.)
  - Extend `AnsatzError` with `LayerMismatch { gammas, betas }` if the two angle
    slices differ in length.
- `pub fn maxcut_pauli_sum(n_qubits, edges: &[(u32,u32)]) -> Result<PauliSum, _>`:
  `H_C = Σ_{(i,j)∈E} ½(I − Z_iZ_j)`. Concretely: one identity term
  `½·|E|` plus one `−½ Z_iZ_j` term per edge. `⟨H_C⟩` is the expected cut value
  (max over basis states = max-cut). Returns a `PauliSum`. (Edge endpoints must
  be `< n_qubits`; out-of-range → error.)

### 2. `aleph-py`: `qaoa_energy` (SV + MPS)
- Add `aleph-mps` to `aleph-py` deps (behind the existing `python` feature path;
  it is a normal dep used only inside `#[cfg(feature="python")]`).
- `qaoa_energy(n_qubits, edges: Vec<(u32,u32)>, gammas: Vec<f64>, betas:
  Vec<f64>, backend: &str) -> PyResult<f64>`: build the QAOA circuit +
  `maxcut_pauli_sum` from `edges`, run on `NaiveSvBackend` (`backend="sv"`) or
  `MpsBackend::with_seed(0).with_max_bond(128)` (`backend="mps"`), return
  `expectation_pauli_sum(&ham)`. Unknown `backend` → `PyValueError`. One
  self-contained call powers the optimizer and all three timing targets (Aer is
  Python-side).

### 3. `scripts/qaoa/`: Python driver
- `gen_graphs.py`: `networkx.random_regular_graph(3, n, seed=...)` for
  n=6/10/14, deterministic; write committed edge-list files
  `scripts/qaoa/graphs/qaoa_n{n}.edges` (one `i j` per line) and the exact
  max-cut value `qaoa_n{n}.maxcut` (brute-force over `2^n` bipartitions; n≤14 →
  ≤16384, trivial).
- `qaoa.py`:
  - `load_graph(n) -> (edges, maxcut)`.
  - `optimize(n, edges, p, restarts) -> (best_energy, gammas, betas)` via
    `scipy.optimize.minimize(method="COBYLA")` maximizing `aleph.qaoa_energy`
    (minimize its negation), best of `restarts` random seeds.
  - `--ratio`: for each (n, p) compute ratio = best_energy / maxcut; print the
    n×p table; **assert ratio ≥ 0.9 at p=3 for n=6 and n=10**; write
    `docs/perf/data/qaoa-results.json` ratios.
  - `--bench`: for each (n, p) time one `qaoa_energy` on `sv`, `mps`, and Qiskit
    Aer (`qiskit_cut_energy`, mirroring `vqe.py`'s Aer path: build the same QAOA
    circuit in Qiskit + `save_expectation_value` of the Max-Cut `SparsePauliOp`),
    single-thread; write medians into `qaoa-results.json`.
  - Fixed angles for `--bench` timing (timing is angle-independent); the optimized
    angles from `--ratio` are what feed the ratio table.
- `test_qaoa.py`: stdlib unittest — graph/maxcut sanity (edge counts, brute-force
  max-cut matches a known small case); `@skipUnless(HAVE_ALEPH)` ratio test
  (n=6 p=3 ≥ 0.9).

### 4. Rust CI gate: `benches/tests/qaoa_maxcut.rs`
- Reads the committed n=6 graph + maxcut. Does a **deterministic p=1 grid
  search** over (γ,β) ∈ a fixed grid (e.g. 48×48 on [0,π)×[0,π/2)), computing
  `⟨H_C⟩` via `build_qaoa` + `maxcut_pauli_sum` + `expectation_pauli_sum` on
  `NaiveSvBackend`. Asserts the grid-best ratio is ≥ a robust p=1 bound (e.g.
  ≥0.6, the known 3-regular p=1 regime) and that the grid actually found a
  non-trivial optimum. This gates the whole Rust QAOA pipeline **in CI with no
  maturin/scipy** (the "p=1 expected ratio" sanity). The ≥0.9@p=3 AC is gated by
  the Python `test_qaoa.py` (COBYLA's natural home), run locally/EPYC with its
  result committed.
- Plus aleph-ir unit tests: `build_qaoa` shape (gate counts for a tiny graph),
  `LayerMismatch` error, `maxcut_pauli_sum` term structure + a hand-checked
  `⟨H_C⟩` on a basis state.

### 5. Report: `docs/perf/qaoa.md` (dedicated)
- `docs/perf/data/qaoa-results.json` (committed): per (n,p) the approximation
  ratio + timing medians for {aleph_sv, aleph_mps, qiskit_aer}, plus graph
  metadata (edges, maxcut).
- `scripts/qaoa/render_report.py`: deterministic renderer → `docs/perf/qaoa.md`
  with (a) an **approximation-ratio table** (rows n=6/10/14 × p=1/2/3), and (b) a
  **timing table** (n×p × {aleph SV, aleph MPS, Aer} ms). Golden-tested like
  `report.py` (stdlib unittest). Header discloses methodology + the two caveats.

## Honesty caveats (baked into `qaoa.md`)
- **MPS likely does not beat SV at n≤14** — the SV state is tiny (≤16K
  amplitudes), so SV constant factors win; MPS's crossover is at larger n
  (VQE.md: "for n≤25 SV may still be faster"). The report states the crossover is
  >14 rather than claiming an MPS win.
- 3-regular QAOA approximation ratio climbs with p; p=1≈0.7 is a sanity figure,
  not gated at 0.9.

## Testing / CI
- Rust unit tests (`build_qaoa`, `maxcut_pauli_sum`) + the p=1 grid gate run in
  the existing `cargo test --workspace` — zero new infra (no maturin in CI).
- `cargo build/test/clippy --workspace` stay green (aleph-py's pyo3 + the new
  `aleph-mps` dep are only compiled under the `python` feature path; `aleph-mps`
  is already a workspace member, no Python needed for the default build).
- Python `test_qaoa.py` + the ratio/bench run via `maturin build --release
  --features python` + `uv pip install` (the P4-04 EPYC recipe).

## EPYC measurement
Single-thread all three backends. Build aleph-py release wheel, run `qaoa.py
--ratio` then `--bench`, commit `qaoa-results.json`, render `qaoa.md`. Same
git-bundle / `reset --hard FETCH_HEAD` / idle-check workflow as [[phase4-status]].

## Out of scope (YAGNI)
Symbolic params, parameter-shift gradients, warm-start/INTERP angle strategies,
MPS bond-dimension sweeps, graphs beyond 3-regular n=6/10/14, weighted Max-Cut,
PyPI packaging.
