# P0-12 — `aleph` CLI binary

**Issue:** P0-12 (see `BACKLOG.md`, GitHub #12)
**Depends on:** P0-08 (parser), P0-09 (Backend trait + NaiveSvBackend), P0-11 (sampling + expectation primitives)
**Date:** 2026-05-25

---

## 1. Goal

Ship a `aleph` command-line binary that runs OpenQASM 3.0 files through
`NaiveSvBackend` and prints results for human consumption. The CLI is
the simplest user-facing surface — useful for demos, scripting CI
smoke tests, and quick interactive experimentation while the Python
bindings (Phase 4) and richer tooling are still ahead.

This ticket targets only the four BACKLOG-listed views (counts /
statevector / expectation / bench) on the one backend that exists
today. JSON output, multi-iteration bench statistics, `--backend`
selection, and shell completions are explicitly deferred (§9).

---

## 2. Scope

### In scope

- New `clap` v4 derive-based CLI in `crates/aleph-cli/`. Two
  subcommands: `run` and `bench`. Auto-generated `--version` / `-V`
  and `--help` / `-h`.
- Four composable `run` views: `--shots <N>`, `--statevector`,
  `--expectation <PAULI>` (repeatable), plus a `--force-statevector`
  escape hatch for n > 10.
- Global `--seed <U64>` flag on `run` and `bench` (default: entropy
  via `NaiveSvBackend::new()`).
- Custom Pauli-string parser (§5) supporting positional `IXZI` form
  with optional `coeff*` prefix (e.g. `1.5*ZZ`, `-0.5*X`).
- Human-readable text output to stdout (§6). Errors and warnings to
  stderr via `anyhow`.
- Module split: `main.rs` / `lib.rs` / `cli.rs` / `exec.rs` /
  `output.rs` / `pauli.rs` (§4).
- `tests/cli.rs` using `assert_cmd` + `predicates` for end-to-end
  coverage; unit tests in each module for parser / formatter /
  business-logic.
- Workspace-dep additions: `clap` v4 with `derive`, `anyhow`,
  `assert_cmd`, `predicates`. README "Quick start" section pointing
  at the new binary.

### Out of scope (see §9 for the full deferred list)

- JSON / machine-readable output, structured exit codes, ANSI colors,
  shell completions, config file, `aleph compile`, `--backend`,
  marginal-qubit statevector, multi-iteration bench statistics.

## 3. Architecture

```
crates/aleph-cli/
├── Cargo.toml          (+ clap, anyhow, assert_cmd, predicates dev-dep)
├── src/
│   ├── main.rs         entry, anyhow::Result, dispatch
│   ├── lib.rs          re-exports for integration tests
│   ├── cli.rs          clap Args / Subcommand derive
│   ├── exec.rs         run_circuit() + bench_circuit() business logic
│   ├── output.rs       format_counts / _statevector / _expectation / _bench
│   └── pauli.rs        parse_pauli_arg("1.5*ZZ" / "ZZ") → PauliString
└── tests/
    └── cli.rs          assert_cmd integration tests
```

`exec` and `output` accept `&mut dyn Write` for testability; `main`
passes `io::stdout()`. `lib.rs` exposes `exec`, `output`, `pauli`,
and `cli` so the integration suite can unit-test them directly while
end-to-end coverage runs the binary through `assert_cmd`.

Dependency direction (no cycles): `cli → exec → {aleph-parser,
aleph-sv, aleph-backend, aleph-core}`; `exec → output`; `pauli →
aleph-core`.

## 4. Module responsibilities

### 4.1 `cli.rs`

Pure clap derive: `Cli { #[command(subcommand)] cmd: Cmd }`, `Cmd::Run
{ qasm: PathBuf, shots: Option<u32>, statevector: bool,
force_statevector: bool, expectation: Vec<String>, seed: Option<u64>
}`, `Cmd::Bench { qasm: PathBuf, seed: Option<u64> }`. No business
logic. Help strings on every field, doc-commented from the BACKLOG
context.

### 4.2 `exec.rs`

```rust
pub fn run_circuit<W: Write>(
    qasm_path: &Path,
    shots: Option<u32>,      // None if no view-flag combo specified
    print_statevector: bool,
    force_statevector: bool,
    expectations: &[String], // raw --expectation args
    seed: Option<u64>,
    out: &mut W,
) -> Result<()>

pub fn bench_circuit<W: Write>(
    qasm_path: &Path,
    seed: Option<u64>,
    out: &mut W,
) -> Result<()>
```

`run_circuit` executes in two phases — **validate-first, then
run-and-print** — so a bad argument doesn't produce partial output:

1. `fs::read_to_string(qasm_path)` and `aleph_parser::parse` →
   `Circuit` (gives us `num_qubits`).
2. Parse every `--expectation` string via `parse_pauli_arg`; for each,
   verify `max(q) < circuit.num_qubits`.
3. If `--statevector` was requested and `num_qubits > 10` and
   `--force-statevector` is absent, return the cap error.
4. Allocate the backend (seeded if `--seed`, else entropy), run the
   circuit once.
5. Dispatch to the requested views in fixed order: counts →
   statevector → expectations.

If the user passed no view flag, step 5 defaults to `shots =
Some(1024)`.

`bench_circuit` times three phases with `std::time::Instant`: parse,
run, sample(1024). Reports each + the sum.

### 4.3 `output.rs`

Free functions, each writes to `&mut dyn Write`:
- `format_counts(out, shots: &[u64], total: u32, num_qubits: u32, seed_label: &str)`
- `format_statevector(out, amps: &[Complex], num_qubits: u32)`
- `format_expectation(out, pauli_raw: &str, value: f64)`
- `format_bench(out, qasm_name: &str, num_qubits: u32, parse: Duration, run: Duration, sample: Duration, total: Duration)`

Counts are histogrammed in-place into a `BTreeMap<u64, u64>` (basis
index → count) before printing; ordering is ascending by basis
index. Zero-count entries are elided.

Amplitude format: `"{:+.16e}"`, one entry per line, with
basis-state label `|q_{n-1}…q_0⟩` and `|a|² = {:.6}`.

### 4.4 `pauli.rs`

```rust
pub fn parse_pauli_arg(raw: &str) -> Result<PauliString, PauliArgError>
```

Grammar (hand-rolled `&str` scanner, no `nom`):

```
pauli_arg     = [ coeff "*" ] pauli_string
coeff         = signed-f64 (parsed via str::parse::<f64>)
pauli_string  = { 'I' | 'X' | 'Y' | 'Z' }+   (q0 = leftmost char)
```

Examples:
- `"ZZ"` → `coeff=1.0, terms=[(0, Z), (1, Z)]`
- `"IXZI"` → `coeff=1.0, terms=[(1, X), (2, Z)]` (`I` dropped at PauliString construction)
- `"1.5*ZZ"` → `coeff=1.5, terms=[(0, Z), (1, Z)]`
- `"-0.5*X"` → `coeff=-0.5, terms=[(0, X)]`
- `""` → error: empty Pauli string
- `"ABC"` → error: invalid character 'A' (allowed: I, X, Y, Z)
- `"ZZ*1.5"` → error: coefficient must precede '*'
- `"1.5*"` → error: empty Pauli string after '*'

`PauliArgError` is a small `thiserror` enum; it converts into
`anyhow::Error` via `.context()` at the call site.

The parser does NOT bounds-check `q < num_qubits` — that's the
caller's job, because the circuit isn't known at parse time. `exec`
matches `pauli.terms.last().map(|(q, _)| *q)` against
`state.num_qubits` and surfaces a clear error if a Pauli term
references a qubit beyond the circuit.

## 5. CLI surface

```text
aleph <COMMAND>

Commands:
  run    Run a QASM circuit and print results
  bench  Run a QASM circuit once and print parse / execute / sample wall-times
  help   Print help (clap default)

Global:
  -V, --version    (clap auto)
  -h, --help       (clap auto)

aleph run <QASM_FILE> [OPTIONS]
  --shots <N>            sample N shots (default: 1024 if no view flag given)
  --statevector          print final state vector (capped at n ≤ 10)
  --force-statevector    bypass the n ≤ 10 cap (foot-gun, opt-in)
  --expectation <PAULI>  compute ⟨ψ|P|ψ⟩; repeatable
  --seed <U64>           RNG seed for reproducibility (default: entropy)

aleph bench <QASM_FILE>
  --seed <U64>           RNG seed (default: entropy); bench reports parse + run + sample(1024)
```

**Defaults:** `aleph run circuit.qasm` (no flags) implies `--shots
1024`. If any view flag is supplied, defaults turn off — only the
requested sections are printed.

**Composability:** `--shots`, `--statevector`, `--expectation` can
co-exist. One backend run, multiple views off the resulting state.

**Statevector cap:** if `state.num_qubits > 10` and the user did not
pass `--force-statevector`, `run` aborts with exit 1 and a clear
stderr message naming the dimension. The cap exists so users don't
accidentally dump 2²⁸ amplitudes to their terminal.

No `version` subcommand — clap's auto `--version`/`-V` is the
convention; matches BACKLOG's intent without duplicating the surface.

## 6. Output examples

### 6.1 Counts

```text
$ aleph run bell.qasm --shots 1024 --seed 0
counts (1024 shots, seed=0):
  |00⟩  511  (0.4990)
  |11⟩  513  (0.5010)
```

Ascending by basis index. Zero-count entries elided. `seed=0` (or
`seed=entropy` when no flag) labels reproducibility.

### 6.2 Statevector

```text
$ aleph run bell.qasm --statevector
statevector (2 qubits, 4 amplitudes):
  |00⟩   +7.0710678118654746e-01 +0.0000000000000000e+00i  |a|² = 0.500000
  |01⟩   +0.0000000000000000e+00 +0.0000000000000000e+00i  |a|² = 0.000000
  |10⟩   +0.0000000000000000e+00 +0.0000000000000000e+00i  |a|² = 0.000000
  |11⟩   +7.0710678118654746e-01 +0.0000000000000000e+00i  |a|² = 0.500000
```

`{:+.16e}` matches Qiskit's `float_roundtrip` precision, so output
can be diffed against fixture amplitudes verbatim.

### 6.3 Expectation values

```text
$ aleph run bell.qasm --expectation ZZ --expectation XX
expectation values:
  ZZ    +1.0000000000000000
  XX    +1.0000000000000000
```

Each `--expectation` argument prints on its own line. Pauli string
is echoed verbatim (the raw `--expectation` arg) for grep-friendliness.

### 6.4 Bench

```text
$ aleph bench bell.qasm --seed 0
bench bell.qasm (n=2):
  parse        45.2µs
  run          12.7µs
  sample(1024) 18.4µs
  total        76.3µs
```

Durations formatted as `{:.1?}` (`Debug` formatter for `Duration`
auto-selects unit). `total` is the sum of the three phases, not the
wall time of the whole process — so it excludes binary startup and
arg parsing.

## 7. Error handling

`main` returns `anyhow::Result<()>`. anyhow auto-prints the error
chain to stderr on `Err`, with exit code `1`. Per CLAUDE.md §
"Error handling": `anyhow::Result` is the right choice for the
CLI / examples layer.

**Single non-zero exit code (`1`)** for any error. CI distinguishes
error categories by message content (anyhow chain is grep-friendly),
not by exit code. The BACKLOG AC says "non-zero on error" — `1`
covers it. Structured exit codes are deferred (§9).

**Error sites and their `.context()`:**

| Site | Context |
|---|---|
| `fs::read_to_string` | `"reading QASM file: {path}"` |
| `aleph_parser::parse` | `"parsing {path}"` (ParseError already carries span) |
| `parse_pauli_arg` | `"parsing --expectation argument {raw}"` |
| `PauliString::new` (invalid coeff/dup) | same as above |
| `q >= state.num_qubits` (Pauli term OOR) | `anyhow!("--expectation {raw} references qubit {q} but circuit has {nq} qubits")` |
| `aleph_backend::run` / `sample` / `expectation_value` | `"running circuit"` (BackendError already specific) |
| `--statevector` without `--force-statevector` when n > 10 | `anyhow!("state vector has 2^{n} = {dim} amplitudes; pass --force-statevector to print anyway")` |

**Example error output:**

```text
$ aleph run missing.qasm
Error: reading QASM file: missing.qasm

Caused by:
    No such file or directory (os error 2)
```

**stdout / stderr split:** all result output (counts, statevector,
expectation, bench) goes to stdout; errors and warnings to stderr.
`println!` lives only in `output::*` (writing through `&mut dyn
Write`); `eprintln!` is on the error path handled by anyhow's
default printer.

## 8. Testing strategy

### 8.1 Unit tests (per module)

**`pauli.rs`** (`#[cfg(test)]` inline):
- `parse_zz` → `(1.0, [Z@0, Z@1])`
- `parse_with_coeff` → `(1.5, [Z@0, Z@1])`
- `parse_negative_coeff` → `(-0.5, [X@0])`
- `parse_drops_identity` → `"IXZI"` gives `[X@1, Z@2]`
- `parse_rejects_empty`
- `parse_rejects_invalid_char`
- `parse_rejects_misplaced_coeff` (`"ZZ*1.5"`)
- `parse_rejects_empty_after_coeff` (`"1.5*"`)
- proptest: round-trip random `PauliString` (Z-only, n ≤ 6) through
  display → `parse_pauli_arg` → equal terms.

**`output.rs`** (`#[cfg(test)]` inline):
- `format_counts_zero_count_elided`
- `format_counts_ordering_ascending`
- `format_counts_seed_label_appears`
- `format_statevector_two_qubits` (golden-string assertion)
- `format_expectation_emits_pauli_raw`
- `format_bench_includes_all_phases`

**`exec.rs`** (`#[cfg(test)]` inline):
- `run_circuit_default_view_is_shots_1024` (no view flag → counts only)
- `run_circuit_seeded_is_reproducible` (two seeded calls into
  `Vec<u8>` → identical bytes)
- `run_circuit_statevector_cap_rejects_n11` (synthetic 11-qubit
  circuit → error)
- `run_circuit_statevector_force_bypasses_cap`
- `run_circuit_expectation_oor_qubit_errors`
- `bench_circuit_writes_four_lines`

### 8.2 Integration tests (`tests/cli.rs`, `assert_cmd` + `predicates`)

```text
bell_state_counts        bell.qasm + --shots 1024 --seed 0 → exit 0, stdout matches "counts (1024 shots, seed=0):" + "|00⟩" + "|11⟩"
bell_statevector         bell.qasm + --statevector → 4 amplitude lines, |a|² = 0.5 on |00⟩ and |11⟩
bell_expectation_zz      bell.qasm + --expectation ZZ → stdout contains "ZZ    +1.000"
bell_multiple_expects    --expectation ZZ --expectation XX → both lines present
ghz_3_default_shots      ghz_3.qasm with no flags → defaults to --shots 1024, prints |000⟩ and |111⟩ only
bench_prints_phases      bench bell.qasm → stdout contains "parse", "run", "sample", "total"
seed_reproducibility     two invocations with --seed 0 produce identical counts output
missing_file_error       run nonexistent.qasm → exit 1, stderr contains "reading QASM file"
parse_error_propagates   malformed QASM → exit 1, stderr contains parse-error message
expectation_oor_qubit    --expectation ZZZ on a 2-qubit circuit → exit 1, stderr "references qubit 2 but circuit has 2 qubits"
expectation_bad_pauli    --expectation "ABC" → exit 1, stderr "invalid character"
statevector_n_cap        run an n=12 circuit with --statevector → exit 1, stderr "pass --force-statevector"
statevector_force        same with --force-statevector → exit 0
help_lists_subcommands   aleph --help → stdout lists run, bench
version_flag             aleph --version → stdout "aleph 0.0.0"
```

### 8.3 Fixtures

Reuse `oracle/circuits/bell_phi_plus.qasm` and
`oracle/circuits/ghz_3.qasm` via
`aleph_oracle::workspace_path` (devs-only). One synthetic 12-qubit
QASM string is built inline in `tests/cli.rs` for the n-cap test
(no new fixture file).

### 8.4 What is NOT tested

- Exact bench timings (machine-dependent). Bench integration test
  checks format presence only.
- Color/TTY behavior (no color output in P0-12).
- Locale-specific number formatting (Rust's default `f64` Debug
  formatter is locale-agnostic; explicit `{:.16e}` is locale-stable).

## 9. Out of scope (deferred)

| Item | Reason / defer-to |
|---|---|
| `--json` / machine-readable output | User chose human-only; defer until a CI consumer needs it. |
| `aleph version` subcommand | clap's auto `--version` covers it. |
| Multi-iteration bench (mean/min/max/stddev) | Defer until cross-backend comparison matters (P1+). criterion benches already cover the in-house perf-tracking need. |
| `--backend` flag | Only one backend exists; flag would have one valid value. Add when MPS / Stab / GPU land. |
| `measure_all` / mid-circuit measurement output | Depends on P0-13+. |
| Marginal `--statevector --qubits 0,2` | `Backend::probabilities` handles marginals; expose later if a use case arises. |
| `aleph compile` / IR-dump command | Useful for Phase-1 optimization debugging; defer. |
| TTY-aware ANSI colors | Keep stdout grep-friendly for now. |
| Shell completions | `clap_complete` is easy to wire later; YAGNI. |
| Config file | Flags suffice at this scale. |
| Structured exit codes (2=parse, 3=backend, …) | Add when CI consumers ask for them. |

## 10. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Output format drift breaks downstream grep | Golden-string unit tests in `output.rs`; format changes require touching the test, surfacing the intent. |
| `assert_cmd` + `predicates` heavy dev-dep | Both are small, well-maintained, dev-only. Pinned at workspace level. |
| Pauli parser surface diverges from a future `PauliString` Display | Round-trip proptest pins parser ↔ Display invariant. If `Display` changes, the proptest catches it. |
| Bench timings noisy on shared dev machines | `bench` subcommand prints raw numbers without "improved/regressed" deltas (criterion is the source of truth for that). Doc the limitation in `--help`. |
| User accidentally prints 28-qubit state vector | Default cap at n=10; `--force-statevector` is the explicit escape hatch. |
| `--seed` flag advertised as reproducible, but RNG sequence changed in P0-11 | Document in `--help` that seed reproduces results _for a given aleph version_; cross-version reproducibility is not promised. |

- Implementation order (drives the plan):
