# P1-09 — 1q gate fusion (design)

**Issue:** [P1-09] Gate fusion pass — adjacent 1q gates
**Phase:** 1, Stage 2 (IR-opt passes)
**Author:** brainstorm 2026-05-29
**Depends on:** P0-07 (Circuit IR), P0-09 (Backend trait + NaiveSv), P1-06 (diagonal-1q kernel — fast-path target)
**Status:** Spec — pending user approval

-----

## 1. Goal

Merge consecutive single-qubit gates on the same qubit into a single 2×2 unitary, exposed as an opt-in IR pass via `Circuit::optimize()`. Preserve the diagonal-flag so the P1-06 SIMD kernel still fast-paths fused diagonal runs.

**Acceptance criteria (from `BACKLOG.md` § P1-09):**

- [ ] Fusion pass implemented.
- [ ] On VQE ansatz: ≥3× reduction in gate count.
- [ ] Result of fused circuit = result of unfused (to ≤ 1e-12).
- [ ] Pass is opt-in via `Circuit.optimize()` or similar.

## 2. Non-goals

- 2q fusion or 2q+1q absorption — that is P1-10.
- Identity / cancellation peephole (`H·H`, `Rz(θ)·Rz(-θ)`) — that is P1-12.
- Commutation-aware reordering — that is P1-11.
- DCE / dead-code elimination — that is P1-13.
- Fixed-point pipeline ("optimise until stable") — defer to whichever later pass first needs it.
- QASM round-trip for fused gates — fused `Unitary1q*` variants stay non-emittable, joining the existing `UnsupportedGate` arm.
- Fusion across `Reset` / `Measure` — these fence, even though a Reset known-state could in principle absorb following 1q gates onto |0⟩ (different pass).
- `Circuit::optimize_with(pipeline)` overload — only the default pipeline is exposed publicly; the `PassPipeline` type is `pub` so power users can construct & run their own.

## 3. Architecture

### 3.1 New `Gate` variant — `Unitary1qDiag`

Extend `aleph_core::gate::kinds::Gate` with:

```rust
Unitary1qDiag(Box<[Complex; 2]>),  // diagonal entries (d0, d1)
```

Box wrapper keeps the enum's discriminant size unchanged (parity with `Unitary1q`/`Unitary2q`).

`Gate` method updates:

| Method        | Behaviour                                                                |
|---------------|--------------------------------------------------------------------------|
| `arity`       | returns `1`                                                              |
| `name`        | returns `"Unitary1qDiag"`                                                 |
| `matrix`      | returns `GateMatrix::M2x2([[d0, 0], [0, d1]])`                            |
| `is_diagonal` | returns `true`                                                            |
| `is_clifford` | returns `false` (we do not bother classifying — fusion is non-Clifford-aware) |
| `inverse`     | returns `Unitary1qDiag([d0.conj(), d1.conj()])`                            |

Parser (`aleph-parser`) does **not** learn `Unitary1qDiag` — it is an internal-only output of fusion. Emit (`aleph-parser::emit`) extends the existing `Unitary1q | Unitary2q → UnsupportedGate` arm to include `Unitary1qDiag`.

### 3.2 Pass infrastructure — `aleph_ir::passes`

New module with:

```rust
pub trait Pass {
    fn name(&self) -> &'static str;
    fn run(&self, circuit: &mut Circuit) -> Result<PassStats, PassError>;
}

#[derive(Debug, Clone, Copy, Default)]
pub struct PassStats {
    pub gates_before: usize,
    pub gates_after: usize,
    pub transformations: u64,  // pass-defined unit (for Fuse1qRuns: # runs of length ≥ 2 collapsed)
}

#[derive(Debug, thiserror::Error)]
pub enum PassError {
    #[error("internal invariant violated: {0}")]
    InternalInvariant(&'static str),
}

pub struct PassPipeline {
    passes: Vec<Box<dyn Pass>>,
}

impl PassPipeline {
    pub fn new(passes: Vec<Box<dyn Pass>>) -> Self;
    pub fn default_pipeline() -> Self;  // = vec![Box::new(Fuse1qRuns)]
    pub fn run(&self, circuit: &mut Circuit) -> Result<PassStats, PassError>;  // aggregate
}
```

The pipeline runs passes in order, mutates the circuit in place, and aggregates `PassStats` (sum of `transformations`, `gates_before` from first pass, `gates_after` from last pass).

### 3.3 `Fuse1qRuns` pass

Implements `Pass`. Single forward walk over `circuit.instructions()` maintaining per-qubit pending state:

```rust
struct Pending {
    start_index: usize,       // index of first instruction in this run (for run-of-1 replay)
    matrix: [[Complex; 2]; 2],
    diag_only: bool,
    run_len: usize,
}
```

Pending is keyed by `qubit: u32` in a `HashMap` (n ≤ 64 in practice, but we do not assume).

**Algorithm** (pseudo-code; method names map to existing IR API at plan time):

```
for (idx, inst) in input.iter().enumerate():
    case Instruction::Gate(g):
        if is_fusible_1q(g):  # arity==1, no controls, qubits.len()==1
            q = g.qubits[0]
            if pending.contains(q):
                pending[q].matrix = g.matrix() · pending[q].matrix
                pending[q].diag_only &= g.is_diagonal()
                pending[q].run_len += 1
            else:
                pending[q] = Pending { start_index: idx, matrix: g.matrix(), diag_only: g.is_diagonal(), run_len: 1 }
        else:
            for q in inst.used_qubits():     # IR API; returns controls + targets
                flush(q)                     # writes 0 or 1 instructions to output
            output.push(inst.clone())
    case Instruction::Barrier(qs):
        for q in qs: flush(q)
        output.push(inst.clone())
    case Instruction::Measure { qubit, .. } | Instruction::Reset(qubit):
        flush(qubit)
        output.push(inst.clone())

# final flush of all pending qubits in stable order
for q in pending.keys().sorted(): flush(q)
```

**Flush of a pending run on qubit q:**

- `run_len == 1`: re-emit the original `Instruction` at `input[start_index]` (clone). This preserves the original gate verbatim; no matrix allocation, no semantic change.
- `run_len ≥ 2 && diag_only`: emit `Instruction::Gate(GateInstance::new(Gate::Unitary1qDiag(Box::new([matrix[0][0], matrix[1][1]])), smallvec![q]))`. `transformations += 1`.
- `run_len ≥ 2 && !diag_only`: emit `Instruction::Gate(GateInstance::new(Gate::Unitary1q(Box::new(matrix)), smallvec![q]))`. `transformations += 1`.

**Matrix-product order (the easy place to get this wrong):** quantum convention applies G₁ first; for an in-IR-order run `[A, B, C]` the fused matrix is `M = C · B · A`. Implementation: per appended gate `g`, compute `M = g.matrix() · M` (left-multiply). Comment cites convention next to the multiply.

**Pass-level invariant:** `gates_after ≤ gates_before`. Per-qubit gate-touch count is also monotone (used as a property test, see §4.2).

### 3.4 `Circuit::optimize()`

```rust
impl Circuit {
    pub fn optimize(&mut self) -> Result<PassStats, PassError> {
        PassPipeline::default_pipeline().run(self)
    }
}
```

Callers who want raw IR simply do not call `optimize()`. AC's "opt-in" satisfied.

## 4. Fusion semantics

### 4.1 What counts as fusible

A `GateInstance` is fusible 1q iff **all** of:

- `gate.arity() == 1`
- `controls` is empty
- `qubits.len() == 1`

Concrete fusible gates: `H, X, Y, Z, S, Sdg, T, Tdg, Rx, Ry, Rz, Phase, U3, Unitary1q, Unitary1qDiag`.

A controlled `H` (i.e. `arity==1` with a non-empty `controls`) is **not** fusible — the effective operation is conditional on the control(s).

### 4.2 What fences a per-qubit run

| Instruction                                | Fences which qubits                                |
|--------------------------------------------|----------------------------------------------------|
| Multi-qubit gate (arity ≥ 2)               | every qubit it lists                               |
| Controlled gate (any arity, controls ≠ ∅)  | target qubits + control qubits                     |
| `Barrier(qs)`                              | every q in `qs`                                    |
| `Measure { qubit, .. }`                    | that qubit                                         |
| `Reset(q)`                                 | that qubit                                         |
| End of circuit                             | all qubits with a pending run                      |

### 4.3 Numerical accuracy

Chaining k 2×2 unitary multiplies in FP64 accumulates ~ `O(k · ε_machine)` error (ε ≈ 2.22e-16). At k = 10⁴ that is ~ 2e-12 — inside the 1e-12 oracle tolerance. Phase 1 accepts this; no Gram-Schmidt at flush. If a later ticket finds drift breaking oracle tests, an ADR will introduce re-orthonormalisation.

### 4.4 Global phase

`Phase(θ)`'s matrix is `diag(1, e^{iθ})` — fusing pure `Phase` gates yields `Unitary1qDiag([1, e^{iΣθ}])` with no introduced global phase. `Rz(θ)` is `diag(e^{-iθ/2}, e^{+iθ/2})` and carries global phase in both entries. The kernel applies the diagonal as-is — backends already handle this via `Gate::matrix()`; no normalisation.

### 4.5 Identity-fused runs are kept

A run that produces a matrix numerically equal to `I` (e.g. `H·H`) emits a single `Unitary1q ≈ I`. Cancellation (drop-if-identity) is P1-12's job; pass composition is `P1-09 → P1-12`.

## 5. Backend wiring

`Unitary1qDiag` routes through the existing apply_1q dispatch in every backend:

- **`NaiveSvBackend`** (`aleph-sv`): classifier matches `is_diagonal() == true` → diagonal scalar path. Unit-tested on a 2-qubit fixture.
- **`SoaSvBackend` AoS + AVX-512** (P1-06's diagonal kernel): same classifier behaviour. Unit-tested on a 4-qubit fixture covering both the AoS and SoA layouts.

No backend implementation changes are expected — `is_diagonal()` is the dispatch key, and `Unitary1qDiag::is_diagonal()` returns `true`. Confirmation tests in §6.4 verify this.

## 6. Testing

### 6.1 Unit tests (`aleph-ir::passes::fuse_1q::tests`)

- Empty circuit → no-op, `PassStats::transformations == 0`.
- Single 1q on q0 → re-emitted unchanged (run-of-1 short-circuit).
- `H; H` on q0 → one `Unitary1q` (≈ I; cancellation is P1-12).
- `S; T; Z` on q0 (all diagonal) → one `Unitary1qDiag` with hand-checked entries.
- `H; S` on q0 (mixed) → one `Unitary1q`.
- `H` on q0; `X` on q1 → two separate runs, each length-1, re-emitted unchanged.
- `Rz(a); H; Rz(b)` on q0 → one `Unitary1q`; matrix compared to hand-computed reference within 1e-14.
- Fence by 2q: `H; CNOT(0,1); H` on q0 → two length-1 runs around CNOT, both re-emitted.
- Fence by Barrier: `H; Barrier([0]); H` on q0 → two length-1 runs.
- Fence by Measure / Reset: `H; Measure(0, c0); H` → two length-1 runs.
- Controlled 1q (`H` with `controls = [1]`) does NOT fuse — flanked by two `H` gates on its target, both flanking gates emit as length-1 runs.
- Mixed per-qubit independence: run-of-2 on q0 interleaved with run-of-3 on q1 in arbitrary IR order — verified per-qubit independence.

### 6.2 Property tests (`proptest`)

Live in `aleph-ir` alongside the pass.

- **Determinism:** `c.clone().optimize()` twice (on independent clones) yields the same `Vec<Instruction>`.
- **Length monotonicity:** `optimized.len() <= original.len()`.
- **Per-qubit touch monotonicity:** for every qubit q, `count(touches(q)) in optimized <= count(touches(q)) in original`.

Strategies reuse `aleph-test`'s existing `arb_op_*` generators.

### 6.3 Equivalence (oracle) tests

Add `fuse_1q_oracle_match` to the existing `aleph-test` proptest harness: generate a random circuit, run unfused through `NaiveSvBackend`, run `circuit.optimize()` then through `NaiveSvBackend`, assert state-vector entries match within 1e-12. Reuses fixture machinery — no new generator.

### 6.4 Backend wiring tests

In `aleph-sv`: dispatch tests confirming `Unitary1qDiag` reaches the diagonal kernel in both `NaiveSvBackend` and the AVX-512 SoA backend. Test fixture: pre-build a `Unitary1qDiag` directly (without fusion), apply to a known basis state, compare to direct matrix-vector multiplication.

## 7. Benchmarks

### 7.1 Hardware-efficient VQE ansatz generator

In `aleph-ir::bench_fixtures` (or equivalent test-helper module):

```rust
pub fn vqe_hea(n_qubits: u32, depth: u32) -> Circuit
```

Per layer: for each qubit emit `Ry(θ₁); Rz(θ₂); Ry(θ₃)`, then a linear CNOT chain `CNOT(0,1), CNOT(1,2), …, CNOT(n-2, n-1)`. With three same-qubit rotations between the CNOT chains, every per-qubit run is length ≥ 3 — so the AC's ≥ 3× reduction is structurally reachable. Concrete θ values are fixed seeds (deterministic).

**Expected reduction:** each per-qubit (Ry, Rz, Ry) triple collapses to one `Unitary1q` (or one `Unitary1qDiag` when the inner Rz is fenced away by a CNOT and only diagonals remain — depends on layer shape). Conservative target: ≥ 3× on `n=12, depth=10`.

### 7.2 Criterion bench (`benches/fuse_1q.rs` in `aleph-ir`)

Measures two things at `n=12, depth=10`:

- `original.len()` vs `fused.len()` — the AC compliance number.
- Wall-clock end-to-end execution on `NaiveSvBackend` (`optimize + run` vs `run` alone) — the user-visible win.

### 7.3 AC compliance check

A companion `#[test]` in the same crate calls `vqe_hea(12, 10)`, optimises, and `assert!`-s `original_len as f64 / fused_len as f64 >= 3.0`. This pins the AC numerically in CI so a future regression cannot land silently.

### 7.4 No EPYC mandate

P1-09 is algorithmic, not SIMD. The layout/codegen traps from P1-03/05/07 do not apply; gate-count ratios are deterministic. Wall-clock numbers can be validated on EPYC opportunistically (not gating).

## 9. Risks

- **`Gate` enum addition is a breaking change** for any external matcher on `Gate`. Internal matchers fixed at compile time; no published API yet. Low risk.
- **Long-chain FP64 drift** (§ 4.3) within tolerance for Phase 1; tracked but not mitigated.
- **VQE ansatz shape choice** — if the chosen `vqe_hea` shape happens to land just under 3× on `n=12, depth=10`, depth can be increased without changing the spec. The AC is "≥ 3× on a VQE ansatz", not "on this exact shape".
- **Bench wall-clock variance** is a comment, not a gate — only the gate-count ratio gates CI.
