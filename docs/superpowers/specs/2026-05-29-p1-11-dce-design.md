# P1-11 — Dead code elimination pass

**Issue:** [P1-11] Dead code elimination pass (BACKLOG.md, GitHub #23)
**Depends on:** P0-07 (`Circuit` IR), `aleph_ir::passes` infrastructure (P1-09)
**Date:** 2026-05-29
**Status:** Approved (brainstorm)

## Goal

Add a third IR optimisation pass, `DeadCodeElim`, that removes gate
instructions whose effect cannot reach any measured qubit. Reverse
data-flow liveness from measurements; entanglement (multi-qubit gates and
controls) propagates liveness; `Reset` severs backward liveness.

## Correctness model (foundational — not optional)

The **observable** of a circuit determines what is "dead":

- If the circuit contains **at least one `Measure`**, the observable is the
  measurement-result distribution. DCE is valid iff it preserves that
  distribution. Removing a gate that has no data-flow path to any measured
  qubit cannot change any measurement outcome, so it is safe. This matches
  the BACKLOG equivalence criterion: "DCE'd vs. original circuit produce
  the same measurement distribution."
- If the circuit contains **no `Measure` instructions**, the observable is
  the full state vector (state-vector backends expose all amplitudes; the
  oracle harness compares them at 1e-12). Removing any gate would change
  the state vector. Therefore **DCE is a no-op on circuits with no
  measurements** — it returns the circuit unchanged.

This no-measurement guard is what makes `DeadCodeElim` safe to include in
`default_pipeline()`: unitary circuits (the bulk of oracle/bench fixtures,
and everything `gate_only()` produces) pass through untouched, so existing
state-vector oracle equivalence is preserved.

## Approach — single-pass reverse-walk liveness

One linear pass over `circuit.instructions` in **reverse**, maintaining a
`live: HashSet<u32>` of qubits whose pre-instruction state can still affect
a measurement. Mirrors the proven structure of `Fuse1qRuns`/`Fuse2q`
(read `&circuit.instructions` directly, build a separate output vec, never
`std::mem::take`).

`touched(inst)` = `inst.used_qubits()` (already returns gate qubits ∪
external controls).

Reverse-walk rules (push every kept instruction onto `kept_rev`):

- **`Measure { qubit, .. }`** — keep; `live.insert(qubit)`. (Liveness root.)
- **`Gate`** on `touched`:
  - if `touched ∩ live ≠ ∅` → **live**: keep; `live.extend(touched)`
    (a gate touching a live qubit can entangle all its qubits into the
    measured outcome, so all become live).
  - else → **dead**: drop it; `transformations += 1`.
- **`Reset(q)`** — keep; then `live.remove(&q)`. A reset writes `q = |0⟩`
  regardless of prior state, so it severs backward liveness on `q`: gates
  earlier than the reset that touch only `q` (now not live) are dead.
- **`Barrier(qs)`** — keep; `live.extend(qs)` (**conservative**: a barrier
  makes its qubits live so no gate fenced by the user is removed; honours
  "passes must not cross a barrier").

After the walk, `kept_rev.reverse()` to restore forward order and assign
to `circuit.instructions`.

### Why this is correct

- **No false positives** (never remove a live gate): a gate is dropped only
  when none of its touched qubits is live, i.e. no data-flow path exists
  from it to any measurement (directly or via entanglement). Liveness is
  monotone-propagated backward, so a dropped gate provably cannot influence
  any retained measurement.
- **Reset-sever with entanglement is safe:** a gate before `Reset(q)` that
  entangled `q` with a live qubit `p` stays live *via `p`* (it's kept and
  re-adds both), so `p`'s dependency is preserved; only gates whose sole
  live link was through `q` (which the reset wipes) become dead.
- **Mid-circuit measurement:** a measured `q` is a root from that point
  backward; gates after it on `q` (forward) are live only if they reach
  some other measurement. Handled by the reverse walk with no special case.
- Measure/Reset/Barrier are **always kept** — DCE removes only `Gate`
  instructions (matches "Remove gates …"). This keeps the pass simple and
  avoids reasoning about removing structural ops.

## Pipeline placement

`PassPipeline::default_pipeline()` becomes:

```rust
Self::new(vec![Box::new(DeadCodeElim), Box::new(Fuse1qRuns), Box::new(Fuse2q)])
```

DCE runs **first**: (a) fusion does no wasted work on doomed gates, and
(b) removing a dead gate can expose new adjacency for fusion. On unitary
circuits the no-measurement guard makes DCE a no-op, so placing it first is
safe for the existing state-vector oracle tests.

## Components

- New file `crates/aleph-ir/src/passes/dce.rs` — `pub struct DeadCodeElim;`
  implementing `Pass`.
- `crates/aleph-ir/src/passes/mod.rs` — `pub mod dce; pub use dce::DeadCodeElim;`
  and append to `default_pipeline()` as the first pass.

`run()` skeleton:

```rust
fn run(&self, circuit: &mut Circuit) -> Result<PassStats, PassError> {
    use crate::Instruction;
    use std::collections::HashSet;

    let input: &[Instruction] = &circuit.instructions;
    let gates_before = input.len();

    // Observable guard: no measurement ⇒ full state is observable ⇒ no-op.
    if !input.iter().any(|i| matches!(i, Instruction::Measure { .. })) {
        return Ok(PassStats { gates_before, gates_after: gates_before, transformations: 0 });
    }

    let mut live: HashSet<u32> = HashSet::new();
    let mut kept_rev: Vec<Instruction> = Vec::with_capacity(input.len());
    let mut transformations: u64 = 0;

    for inst in input.iter().rev() {
        match inst {
            Instruction::Measure { qubit, .. } => {
                live.insert(*qubit);
                kept_rev.push(inst.clone());
            }
            Instruction::Reset(q) => {
                kept_rev.push(inst.clone());
                live.remove(q);
            }
            Instruction::Barrier(qs) => {
                for q in qs { live.insert(*q); }
                kept_rev.push(inst.clone());
            }
            Instruction::Gate(_) => {
                let touched = inst.used_qubits();
                if touched.iter().any(|q| live.contains(q)) {
                    for q in &touched { live.insert(*q); }
                    kept_rev.push(inst.clone());
                } else {
                    transformations += 1; // dead gate dropped
                }
            }
        }
    }

    kept_rev.reverse();
    let gates_after = kept_rev.len();
    circuit.instructions = kept_rev;
    Ok(PassStats { gates_before, gates_after, transformations })
}
```

The pass is infallible (returns `Ok`), like the other passes;
`PassError::InternalInvariant` stays reserved.

## Testing (unit + property + oracle)

### Unit (`mod tests` in `dce.rs`)

- **dead branch removed:** `H(0); CNOT(0,1); X(2); Measure(0); Measure(1)` →
  `X(2)` dropped (q2 unmeasured, unentangled with {0,1}); H + CNOT kept;
  `transformations == 1`.
- **reset-sever:** `H(0); Reset(0); X(0); Measure(0)` → `H(0)` dropped
  (wiped by the reset), `X(0)` and `Reset(0)` kept; `transformations == 1`.
- **barrier conservative:** `X(2); Barrier([2]); Measure(0)` → `X(2)` **kept**
  (barrier made q2 live); `transformations == 0`.
- **entanglement keeps alive:** `X(2); CNOT(2,0); Measure(0)` → CNOT touches
  live q0 → both kept; the `X(2)` then touches live q2 → kept;
  `transformations == 0`.
- **no-measurement guard:** a unitary circuit (`H(0); CNOT(0,1)`, no
  Measure) → unchanged, `transformations == 0`.
- **no false positives:** a fully-live circuit (every qubit measured) loses
  nothing.
- **mid-circuit measure:** `H(0); Measure(0); X(1)` (only q0 measured) →
  `X(1)` dropped; `H(0)`, `Measure(0)` kept.

### Property (`tests/dce_properties.rs`, proptest)

Strategy `arb_circuit_emittable` (as fuse_2q_properties), run `DeadCodeElim`
alone:
1. **monotonicity:** `gates_after ≤ gates_before`.
2. **idempotence:** a second `DeadCodeElim` removes nothing more.
3. **determinism:** two independent runs agree structurally.

### Oracle (`crates/aleph-sv/tests/dce_oracle.rs`)

- **measurement-distribution equivalence:** for circuits **with**
  measurements, the DCE'd circuit and the original produce the same
  measurement distribution. Reuse the existing distribution-oracle harness
  (`run_distribution_oracle`, in use since P0-11) / `NaiveSvBackend`
  sampling. Tolerance per CLAUDE.md: 1e-5 on probabilities at 100k shots
  (or compare exact per-outcome probabilities computed from amplitudes on
  the measured subspace). The plan pins the exact helper signatures.
- **state-vector preserved on unitary circuits via full pipeline:** the
  existing `fuse_1q_oracle` / `fuse_2q_oracle` (which call `optimize()`,
  now including DCE) must still hold at 1e-12 — confirms the no-measurement
  guard keeps DCE a no-op there.

### Acceptance-criterion fixture

Add `ancilla_compute(n_data)` to `bench_fixtures.rs`: a circuit that
prepares the data qubits, computes an **ancilla register** entangled only
among itself (or reset before measurement), and measures **only the data
qubits**. After DCE, the ancilla-only gates that never reach a data
measurement are removed. Document the expected gate-count reduction in a
fixture test (`ancilla_compute_dce_reduces` asserting strictly fewer gates
after `DeadCodeElim`), satisfying "test corpus shows reduction on at least
one fixture".

## Non-goals

- Removing `Measure` / `Reset` / `Barrier` instructions.
- Classical-bit liveness (a measured-but-unused clbit) — out of scope;
  we key liveness on qubits, and every `Measure` is treated as observable.
- Commutation/reordering (P1-13) or constant-folding of gate parameters.
- Cross-`Reset` re-use analysis beyond the single-qubit sever rule.
