# P4-02 — Grover Benchmark — Design

**Issue:** #40 (P4-02). **Depends on:** P1-14, P4-01 (the Phase-4 framework). **Milestone:** Phase 4.
**Date:** 2026-06-06. **Status:** approved, pre-implementation.

## Goal

Add **Grover** as the second consumer of the Phase-4 benchmark/report framework
(stood up in P4-01), satisfying the P4-02 acceptance criteria:

- Grover converges for the tested sizes (n = 4, 8, 12, 16).
- A benchmark report row (a Grover section in `docs/perf/phase4.md`).
- Testing: marked-state probability **> 0.9** after the optimal √N iterations.

## Decisions (locked during brainstorming)

1. **Optimal iterations, no-ancilla MCX, n ∈ {4,8,12,16}.** Iterations =
   `round(π/4·√(2ⁿ))` → {4:3, 8:13, 12:50, 16:201}. Real transpiled gate counts:
   268 / 17 974 / 264 312 / 2 258 854. The state vector is tiny (n≤16 ⇒ ≤1 MiB,
   cache-resident), so even 2.26 M gates at n=16 is ~seconds for aleph / a few
   minutes for Aer single-thread — tractable. **No ancilla qubits, no qubit-cap
   change** (all n ≤ 16 ≪ 28).
2. **Repurpose the `grover` family** in `run.py` to these optimal-iteration sizes.
   The old `grover_n15..25_iters5.qasm` fixtures stay on disk as frozen
   Phase-1/2 artifacts (tier1/phase2 benches still read them) but are no longer
   regenerated by `run.py`'s grover family.
3. **Convergence test: n=4,8,12 in CI, n=16 `#[ignore]`** (CLAUDE.md
   nightly-ignored-tests). n=16 still appears in the benchmark row.

## What this reuses (from P4-01)

- `build_grover(n, iters)` in `run.py` — Qiskit `GroverOperator` over an oracle
  that phase-flips |0…01⟩ (X-layer + H·mcx·H + X-layer), already present.
- The corpus → aleph criterion + Aer → unified JSON → `report.py` → `phase4.md`
  pipeline. `report.py` is **family-agnostic** and already has `"grover"` in its
  title map, so a Grover section appears automatically once grover rows land in
  the two result JSONs.
- The `oneshot` single-shot timer (raised cap + `elapsed_ms`) for the heavy size.
- `scripts/bench-report/{extract_criterion.py, report.py}` and their unittest.

## Components

### 1. `run.py` — corpus + Aer

- Add `def grover_optimal_iters(n): return max(1, round(pi/4 * sqrt(2**n)))`.
- `FAMILY_SIZES["grover"] = [4, 8, 12, 16]`.
- `FAMILY_BUILDERS["grover"] = lambda n: build_grover(n, grover_optimal_iters(n))`.
- `workload_name` for grover → `grover_n{n}_iters{grover_optimal_iters(n)}`.
  (`GROVER_ITERS = 5` becomes unused by the active matrix; keep the constant +
  a comment noting the legacy fixtures, or remove it — the implementer picks the
  cleaner option, documenting the legacy fixtures either way.)
- **Cost-based `timing_runs_for`.** Today it keys on `n` alone, which mis-budgets
  Grover (n=16 is cheap-state but 2.26 M gates). A single Aer statevector run
  costs ≈ `gate_count × 2ⁿ`. Change the signature to
  `timing_runs_for(n, gate_count)` and pick runs from that cost estimate
  (e.g. cost > 1e12 → 1; > 1e11 → 2; > 1e10 → 3; > 1e9 → 5; else 10). This must
  preserve the existing QFT budget (QFT-30: 2205 × 2³⁰ ≈ 2.4e12 → 1–2 runs, as
  before) and give Grover-16 (≈1.5e11 → 2 runs) a small count. The main loop
  already computes `gate_count` before timing, so pass it in.

### 2. aleph bench — `benches/benches/phase4_grover.rs`

- Mirror `phase4_qft.rs`: read the committed corpus QASM
  `scripts/qiskit-baseline/circuits/grover_n{n}_iters{opt}.qasm`, run via
  `run_optimized` on `NaiveSvBackend`, criterion group `phase4_grover`.
- SMALL_N = {4, 8, 12} (criterion, fast). n=16 (2.26 M gates) measured via the
  `oneshot` single-shot path in the EPYC run, not criterion — same split as
  QFT n=30. (The bench may include n=16 behind `scaling-bench` for spot checks,
  but the report number comes from `oneshot`.)
- Filename in the bench must match the actual corpus name, which embeds the
  iteration count (`grover_n16_iters201.qasm`). The bench builds the path from
  `(n, optimal_iters(n))`; define `optimal_iters` in the bench too (tiny, const
  table or the round formula) so the path matches the generator.

### 3. Convergence test (the AC)

A test that, for each n, parses the committed `grover_n{n}_iters{opt}.qasm`, runs
it on `NaiveSvBackend`, and asserts the marked basis state has probability > 0.9.

- The oracle marks |0…01⟩, which is **amplitude index 1** in aleph's array
  (verified empirically: n=4 optimal Grover → dominant state `|0001⟩` at
  p = 0.961; |0…01⟩ = integer 1 for any n). The test asserts both (a)
  `amps[1].norm_sqr() > 0.9` (the marked state is amplified) and (b) index 1 is
  the max-probability state (we amplified the *right* state, not just *some*
  state).
- n=4,8,12 run in normal `cargo test`; n=16 is a separate `#[ignore]`d test.
- Lives where it can read the corpus + run the backend (e.g. a `tests/`
  integration test in `aleph-benches`, or `benches/src/lib.rs` tests). No aleph
  Grover builder is added — the corpus QASM is the single source of truth.

### 4. Report

The EPYC measurement appends grover rows to `docs/perf/data/phase4-aleph.json`
and a grover-augmented `docs/perf/data/phase4-aer.json`, then re-runs `report.py`
→ `docs/perf/phase4.md` now has both a QFT and a Grover section. Single-thread
both sides (fair, per the P4-01 methodology lesson). `report.py` reproduces the
markdown byte-identically.

## Testing & reproducibility

- **Convergence** (AC): marked-state p > 0.9 at n=4,8,12 (CI) + n=16 (ignored).
- **Corpus drift guard:** regenerating grover_n{4,8,12,16} is byte-identical to
  the committed files (deterministic; `build_grover` has no RNG).
- **report.py** determinism already golden-tested in P4-01; adding a family
  needs no new tooling test.
- **EPYC run:** documented in `scripts/bench-report/README.md` (extend the QFT
  instructions with the grover workloads); heavy n=16 gated/oneshot, idle-box
  rule per CLAUDE.md.

## Out of scope (YAGNI)

- Multi-marked-state Grover, amplitude-amplification variants.
- Ancilla-based MCX (not needed — small state makes no-ancilla tractable).
- Touching the legacy `grover_n15..25_iters5` fixtures or the tier1/phase2 benches.
- P4-03..07 (each its own ticket; the framework now carries two families).
