# P4-04 — VQE benchmark, H₂ molecule (design)

**Issue:** #42 (`area:bench`, `type:test`, `priority:critical`, Phase 4, est. L)
**Depends on:** P1-14. Builds on the Phase-4 framework (P4-01..03).
**Date:** 2026-06-06

## Goal

A Variational Quantum Eigensolver benchmark for the H₂ ground-state energy with a
hardware-efficient ansatz, driven from Python through new (minimal) `aleph-py`
bindings. Delivers: (1) convergence to the H₂ ground-state energy within chemical
accuracy of FCI, and (2) a "time per energy evaluation" benchmark at 4/6/8 qubits
comparing aleph vs Qiskit, rendered into `docs/perf/phase4.md`.

This is a single combined ticket spanning two coupled stages — minimal `aleph-py`
bindings, then the VQE-H₂ benchmark that consumes them.

## Acceptance criteria (from BACKLOG)

- [ ] VQE converges to known H₂ ground-state energy → Rust integration test
  (rotosolve on the real H₂ 4-qubit Hamiltonian) + the Python driver.
- [ ] Benchmark: time per energy eval at 4, 6, 8 qubits → Python perf harness →
  VQE rows in `phase4.md`.
- [ ] Comparison with Qiskit / PennyLane → the report row IS the comparison
  (aleph vs Qiskit energy-eval time, single-thread both sides).
- Testing: energy within chemical accuracy (1.6e-3 Hartree) of the FCI result.

## Background (what already exists)

- `Backend::expectation_value(&state, &PauliString) -> f64` on every backend
  (`crates/aleph-sv/src/measure.rs:157` etc.), with a Z-diagonal fast path.
- `Pauli` / `PauliString` (coeff + sorted terms) in `crates/aleph-core/src/pauli.rs`.
- All parametric gates `Ry/Rx/Rz/U3` with `Param::Concrete(f64)`
  (`crates/aleph-core/src/gate/kinds.rs`).
- `vqe_hea(n, depth)` fixture with hardcoded seeded angles
  (`crates/aleph-ir/src/bench_fixtures.rs`).
- `aleph-py` is an **empty placeholder** (no pyo3, `cdylib`+`rlib`).
- `report.py` already maps `"vqe": "VQE"`.

What is missing and this ticket adds: a `PauliSum` type, a Σcᵢ⟨Pᵢ⟩ energy
helper, a parameterized HEA builder, the pyo3 bindings, the H₂ Hamiltonian data,
and the Python rotosolve driver + perf harness.

Deferred (VQE.md optimization ladder, NOT this ticket): symbolic parameters,
Pauli grouping, parameter-shift gradients + intermediate-state caching, MPS
routing, SciPy/argmin optimizers.

## Architecture — five layers

### 1. `aleph-core`: `PauliSum` + text format
- `pub struct PauliSum { pub terms: Vec<PauliString> }` (each `PauliString`
  already carries its `coefficient`). Backend-agnostic data ⇒ lives in core.
- Text format, one term per line: `<coeff> <pauli>` where `<pauli>` is an
  n-char string over `{I,X,Y,Z}` (qubit 0 = leftmost char), e.g.
  `-0.4804 ZIII`, `0.1741 IZIZ`, `0.0453 XXYY`. Blank lines / `#` comments
  ignored. `PauliSum::parse(src, n_qubits) -> Result<PauliSum, _>` maps each
  line to a `PauliString` (drop `I` positions). This is the single source of
  truth both aleph and Qiskit load.

### 2. `aleph-backend`: energy primitive
- `pub fn expectation_pauli_sum<B: Backend>(backend: &mut B, state: &B::State,
  ham: &PauliSum) -> Result<f64, BackendError>` = `Σ
  backend.expectation_value(state, term)` (each `PauliString` carries its
  coeff). Thin, allocation-free loop over the existing per-Pauli primitive.

### 3. `aleph-ir`: parameterized HEA builder
- `pub fn build_hea(n_qubits: u32, depth: u32, params: &[f64]) -> Circuit`.
  Layout (the canonical "Ry + linear-CNOT" hardware-efficient ansatz):
  ```
  for l in 0..depth:
      Ry(params[l*n + q]) on each qubit q        # rotation layer
      CNOT(q, q+1) for q in 0..n-1               # linear entangler
  Ry(params[depth*n + q]) on each qubit q        # final rotation layer
  ```
  `params.len() == n*(depth+1)` (validated). Ry-only ⇒ real amplitudes, which
  suffices for the real-symmetric H₂ Hamiltonian's real ground state.
  The existing `vqe_hea` fixture is refactored to call `build_hea` with its
  seeded angles (keeps its IR-pass tests intact).

### 4. `aleph-py`: minimal pyo3 bindings (feature-gated)
- Add `pyo3` (with `extension-module`, `abi3-py312`) as an **optional**
  dependency, gated behind a `python` feature. The pyo3 `#[pymodule]` and all
  `#[pyfunction]`s sit behind `#[cfg(feature = "python")]`. **`cargo build
  --workspace` / `cargo test --workspace` (no feature) build aleph-py exactly as
  today** (empty rlib, no Python interpreter needed) → existing Rust CI stays
  green. `maturin develop --features python` produces the Python module.
- Surface (kept tiny — two entry points):
  - `PauliSum.load(path: str, n_qubits: int) -> PauliSum` (wraps
    `aleph_core::PauliSum::parse`).
  - `hea_energy(n_qubits: int, depth: int, thetas: Sequence[float], ham:
    PauliSum) -> float`: `build_hea` → run on `NaiveSvBackend` (verbatim `run`)
    → `expectation_pauli_sum`. One call = one energy evaluation; powers both the
    optimizer loop and the perf timing.
- `crates/aleph-py/pyproject.toml` (maturin backend) added.

### 5. Python VQE driver + benchmark (`scripts/vqe/`)
- `scripts/vqe/hamiltonians/vqe_n{4,6,8}.txt` — committed Pauli-sum data:
  - **n=4**: the real H₂/STO-3G/Jordan-Wigner Hamiltonian at bond length
    0.735 Å (15 terms, literature coefficients — cited in `gen_hamiltonians.py`;
    the convergence test self-validates them).
  - **n=6, n=8**: a deterministic molecular-style scalable Pauli sum
    `H = Σ_i h_i Z_i + Σ_{i<j} J_ij Z_iZ_j + Σ_{i<j} K_ij (X_iX_j + Y_iY_j)`
    with bounded deterministic coefficients (O(n²) terms; n=6→51, n=8→92, in
    line with VQE.md's per-n term counts). Convergence is NOT asserted on these
    — they exist only to scale the energy-eval performance point.
- `scripts/vqe/gen_hamiltonians.py` — emits the three data files
  deterministically (no PySCF dependency; H₂ from cited constants).
- `scripts/vqe/rotosolve.py` — analytic per-parameter optimizer (Ostaszewski et
  al. 2021): for each θⱼ, evaluate energy at `{θⱼ, θⱼ+π/2, θⱼ−π/2}`, set θⱼ to
  the closed-form sinusoid minimum; sweep until ΔE < tol. Calls
  `aleph.hea_energy`.
- `scripts/vqe/vqe.py` — driver. `--converge` runs rotosolve on H₂ 4q from a
  fixed θ₀ and prints the final energy (must reach FCI ± 1.6e-3). `--bench`
  times one energy eval at n=4/6/8 for **aleph** (`hea_energy`) and **Qiskit**
  (Aer `method='statevector'`, `max_parallel_threads=1`, manual ⟨H⟩ over the
  same loaded Hamiltonian + same HEA built in Qiskit), single-thread both sides,
  and writes medians to a results JSON.
- `scripts/vqe/test_vqe.py` — stdlib `unittest`: Hamiltonian-file round-trip,
  rotosolve-on-a-toy-Hamiltonian sanity, and (when aleph-py is importable) the
  H₂ convergence. Skips gracefully if aleph-py isn't built.

## Data flow into the report

VQE departs from the criterion path (the metric is Python-driven energy-eval
time, which is the honest VQE inner-loop cost). `scripts/vqe/vqe.py --bench`
produces both aleph and Qiskit medians in one process. Merge into the existing
`docs/perf/data/phase4-{aleph,aer}.json` (family `vqe`, n=4/6/8), append a VQE
note to `phase4-meta.json`, re-run `report.py` → a `## VQE` section appears
automatically (sorted after QFT/QPE/Grover). README gets a "Adding VQE" note.

## Testing / CI

- **Rust unit tests** (existing `cargo test --workspace`, zero new infra):
  `PauliSum::parse` round-trip + error cases; `expectation_pauli_sum` on a known
  state (e.g. ⟨Z⟩ on |0⟩, a 2-term sum on a Bell state); `build_hea` shape +
  param-count validation + equivalence to a hand-built small circuit.
- **Rust integration test** `benches/tests/vqe_h2_convergence.rs` (the
  `aleph-benches` crate already depends on core/ir/backend/sv and resolves
  workspace-root paths via `CARGO_MANIFEST_DIR/..`, exactly like
  `qpe_accuracy.rs`): a pure-Rust rotosolve on the committed H₂ 4q Hamiltonian
  (same algorithm as the Python driver, ~40 lines) from a fixed θ₀, asserting
  final `E ≤ −1.1373 + 1.6e-3 Ha`. **This gates AC1 in the existing Rust CI
  without needing maturin/Python in CI** — robust, no shared-runner risk. (The
  Hamiltonian data file is the single source of truth shared with Python.)
- **Python** (`scripts/vqe/test_vqe.py`): run locally / on EPYC after
  `maturin develop --features python`. The user-facing deliverable; its
  convergence + perf numbers are committed. **No maturin CI job** (the Rust
  integration test already gates the same convergence; avoids touching the shared
  self-hosted runner).
- `cargo build/test --workspace`, `cargo clippy --workspace --all-targets -D
  warnings`, `cargo fmt --check` must stay green — guaranteed by the pyo3 feature
  gate (default build sees no pyo3).

## EPYC measurement

Single-thread both sides. Build aleph-py via `maturin develop --features python`
into the reusable qiskit venv; run `scripts/vqe/vqe.py --bench` (aleph + Qiskit
in one process). Merge medians into the phase4 JSONs, update meta, re-render
`report.py`. Same git-bundle / idle-check / `~/.rustup/.../bin` workflow as
[[phase4-status]]. VQE.md Phase-4 target: per-eval within ~1.3× of Qiskit.

## Risks / decisions

- **pyo3 build breaking `cargo build --workspace`** → mitigated by the `python`
  feature gate (default build never compiles pyo3).
- **H₂ coefficient transcription** → mitigated by the convergence test (wrong
  coeff ⇒ misses FCI ⇒ test fails).
- **HEA depth sufficiency for H₂** → Ry-only reaches the real H₂ ground state;
  the plan validates the depth empirically (raise if convergence misses).
- **abi3 wheel portability** → `abi3-py312` matches the venv's Python 3.12.

## Out of scope (YAGNI)

Symbolic parameters, Pauli grouping, parameter-shift gradients, intermediate-state
caching, SciPy/argmin/nlopt, MPS routing, larger molecules (LiH/H₂O), PyPI
packaging (P4-08). The bindings expose only what VQE needs.
