# [P5.5-01] Metal foundation: device/buffer/pipeline + build & CI — Design

> Status: approved (brainstorm 2026-06-14). Source of truth for the PR.
> Issue: #171. Milestone: Phase 5.5 — Apple/Metal GPU.

## Goal

Stand up the `aleph-metal` crate skeleton and prove an **end-to-end Metal
compute dispatch** before any physics lands. This is pure plumbing: a device,
a command queue, a host-visible buffer, a runtime-compiled pipeline, and one
smoke kernel that runs on the GPU and returns the correct result host-side.

No statevector, no FP32 kernels, no gate logic — those are P5.5-02 and later.
The deliverable is the foundation those tickets build on, plus the CI leg that
keeps it honest.

## Context

Phase 5 (CUDA) is blocked on hardware. Phase 5.5 targets Apple/Metal GPUs,
which we can actually build and test on (this repo's dev box is Apple Silicon).
The referenced `2026-06-13-phase5.5-metal-gpu-design.md` umbrella spec was never
committed to the repo and there is no `[P5.5-01]` section in `BACKLOG.md`; the
GitHub issue body is therefore the only inherited source of truth, and this
document supersedes it where they differ (see "Deviations" below).

## Acceptance Criteria (from issue #171)

1. `cargo build -p aleph-metal --features metal` builds on macOS; default +
   Linux CI unchanged.
2. Smoke kernel runs on the GPU, correct host-side.
3. macOS CI leg green.

## Deviations from the issue text (decided in brainstorm)

The issue body prescribes "build.rs precompiles .metal -> .metallib via
`xcrun`". We deviate on the *mechanism* while satisfying the *intent* (AC #2:
a smoke kernel that runs correctly on the GPU):

- **Shader compilation: runtime compile from MSL source**, via
  `device.new_library_with_source()`, instead of an offline `xcrun metal ->
  .metallib` build step. Rationale: on Xcode 26 the Metal compiler CLI is a
  separate downloadable component (`xcodebuild -downloadComponent
  MetalToolchain`) that is **not** installed on the dev box and is not
  guaranteed on GitHub-hosted macOS runners. The runtime compiler ships with
  the Metal framework itself, needs no `xcrun`, no `metallib` tool, and no
  toolchain component — so it works locally and in CI today. A future ticket
  can add offline `.metallib` precompilation as an optimization if shader
  count/compile-time ever warrants it; it is not needed to prove the
  foundation.

- **CI: graceful GPU skip.** GitHub-hosted macOS runners do not reliably expose
  a usable Metal device to headless jobs. The smoke test therefore *builds*
  unconditionally (the real regression risk) and *executes* the kernel only
  when a device is present; with no device it prints a skip note and passes.
  This keeps the macOS leg green regardless of runner GPU while still asserting
  correctness wherever a GPU exists (always, locally).

## Architecture

New crate **`aleph-metal`**, added to the workspace `members` list. It compiles
to an **empty library** on every target/feature combination except
macOS-with-`metal`-feature, so existing Linux (self-hosted) and default-macOS
builds are unaffected by construction.

### Crate manifest & gating

```toml
# crates/aleph-metal/Cargo.toml
[package]
name = "aleph-metal"
version.workspace = true
edition.workspace = true
rust-version.workspace = true
license.workspace = true
repository.workspace = true
authors.workspace = true

[features]
default = []
metal = ["dep:metal", "dep:bytemuck"]

# Target-cfg'd so the macOS-only `metal` crate is never resolved on Linux.
[target.'cfg(target_os = "macos")'.dependencies]
metal    = { version = "0.30", optional = true }
bytemuck = { version = "1",    optional = true }

[dependencies]
thiserror.workspace = true
```

`metal` crate version is the latest 0.x (metal-rs) compatible at implementation
time; `0.30` is the planning pin and will be confirmed against `cargo` when the
crate is created. `bytemuck` is added to `[workspace.dependencies]`.

All GPU-touching code is gated:

```rust
#[cfg(all(target_os = "macos", feature = "metal"))]
mod context;
#[cfg(all(target_os = "macos", feature = "metal"))]
mod buffer;
```

Consequences:
- Linux `cargo build --workspace`: empty crate, `metal`/`bytemuck` not resolved.
- Default macOS `cargo build --workspace`: empty crate (feature off).
- `cargo build -p aleph-metal --features metal` on macOS: full crate.

### Modules (small, single-purpose)

- **`src/lib.rs`** — crate-level module doc; cfg-gated `mod`/`pub use`; crate
  `Error` enum.
- **`src/context.rs`** — `MetalContext`.
- **`src/buffer.rs`** — `DeviceBuffer<T>`.
- **`src/shaders/smoke.metal`** — MSL source, embedded via `include_str!`.
- **`tests/smoke.rs`** — end-to-end GPU dispatch (graceful skip).

### `Error` (crate-local, `thiserror`)

```rust
#[derive(Debug, thiserror::Error)]
pub enum Error {
    #[error("no Metal device available on this system")]
    NoDevice,
    #[error("Metal shader compilation failed: {0}")]
    ShaderCompile(String),
    #[error("Metal pipeline creation failed: {0}")]
    PipelineCreation(String),
}
```

`NoDevice` is the value the smoke test pattern-matches to decide skip-vs-run.

### `MetalContext` (`context.rs`)

Owns the long-lived GPU handles and the shader→pipeline path. One clear purpose:
hand out a device + queue and turn MSL source into a compute pipeline.

```rust
pub struct MetalContext {
    device: metal::Device,
    queue:  metal::CommandQueue,
}

impl MetalContext {
    /// Acquire the system-default GPU. `Err(Error::NoDevice)` when none exists
    /// (headless CI) — callers use this to skip GPU work gracefully.
    pub fn new() -> Result<Self, Error>;

    pub fn device(&self) -> &metal::Device;
    pub fn queue(&self)  -> &metal::CommandQueue;

    /// Runtime-compile an MSL source string into a library.
    fn compile_library(&self, src: &str) -> Result<metal::Library, Error>;

    /// Compile `src` and build a compute pipeline for `entry`.
    pub fn make_compute_pipeline(
        &self,
        src: &str,
        entry: &str,
    ) -> Result<metal::ComputePipelineState, Error>;
}
```

`compile_library` uses `new_library_with_source` with default
`CompileOptions`; errors map to `Error::ShaderCompile`. `make_compute_pipeline`
looks up the function and builds `new_compute_pipeline_state_with_function`,
mapping failures to `Error::PipelineCreation`.

### `DeviceBuffer<T>` (`buffer.rs`)

A typed, host-visible GPU buffer over `MTLBuffer` with `StorageModeShared`
(unified memory on Apple Silicon → zero-copy host views).

```rust
pub struct DeviceBuffer<T: bytemuck::Pod> {
    buf: metal::Buffer,
    len: usize,
    _marker: PhantomData<T>,
}

impl<T: bytemuck::Pod> DeviceBuffer<T> {
    /// Allocate a shared-storage buffer initialized from `data`.
    pub fn from_slice(ctx: &MetalContext, data: &[T]) -> Self;
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
    pub fn metal_buffer(&self) -> &metal::Buffer; // for binding in encoders
    pub fn as_slice(&self) -> &[T];               // host view over contents()
    pub fn as_mut_slice(&mut self) -> &mut [T];   // host view over contents()
}
```

`T: bytemuck::Pod` bounds the byte reinterpret to be sound and self-document the
POD contract (consistent with `AlignedBuf` in P2-02). The single `unsafe`
(`std::slice::from_raw_parts` over `buf.contents()`) carries a SAFETY block:
`contents()` is non-null and valid for `len * size_of::<T>()` bytes for the
buffer's lifetime under shared storage; `Pod` guarantees every bit pattern is a
valid `T`. `len == 0` returns an empty slice without dereferencing the pointer.

### Smoke shader (`shaders/smoke.metal`)

```metal
#include <metal_stdlib>
using namespace metal;

kernel void smoke_double(device float* buf [[buffer(0)]],
                         uint i [[thread_position_in_grid]]) {
    buf[i] = buf[i] * 2.0;
}
```

Embedded with `include_str!`. Doubling is trivially verifiable and exercises a
read-modify-write over unified memory.

## Data flow (smoke test)

1. `MetalContext::new()` → device + queue (or `NoDevice`).
2. `make_compute_pipeline(SMOKE_SRC, "smoke_double")`.
3. `DeviceBuffer::from_slice(&ctx, &[1.0, 2.0, 3.0, ...])` (N floats).
4. Command buffer → compute encoder → set pipeline, bind buffer at index 0,
   dispatch N threads (1 thread/element) → end → commit →
   `wait_until_completed`.
5. `buf.as_slice()` → assert each `out[i] == 2.0 * in[i]`.

## Testing

- **Unit (`buffer.rs`, behind cfg):** round-trip a slice through
  `DeviceBuffer::from_slice` → `as_slice`; mutate via `as_mut_slice`, observe.
  Requires a device (allocation needs one), so it also guards on
  `MetalContext::new()` and skips when absent.
- **Integration (`tests/smoke.rs`):** the full data flow above. If
  `MetalContext::new()` is `Err(NoDevice)`, `eprintln!` a skip note and `return`
  (the test passes). Otherwise run and assert to 0 tolerance (exact f32
  doubling is bit-exact). Locally on Apple Silicon this executes for real.

Per project convention, no `unwrap`/`expect` in library code; tests may
`unwrap`.

## CI

Extend the **existing `test-macos` job** in `.github/workflows/ci.yml` (runs on
`macos-latest`, stable + beta, already builds/tests `--workspace`). Append:

```yaml
- run: cargo build  -p aleph-metal --features metal
- run: cargo test   -p aleph-metal --features metal
- run: cargo clippy -p aleph-metal --features metal -- -D warnings
```

- AC #1 (default + Linux unchanged): the empty-crate compile is already
  exercised by the existing workspace fmt/clippy/test legs on Linux and default
  macOS; nothing there changes behavior.
- AC #2 (kernel runs correct): `cargo test --features metal` runs the smoke
  test — really on the dev box, best-effort on CI (skip if no device).
- AC #3 (macOS leg green): the graceful skip guarantees green regardless of
  runner GPU.

No new CI job is added; the self-hosted Linux runner is untouched.

## Out of scope (YAGNI)

- Statevector / amplitude layout, any quantum gate kernels (P5.5-02+).
- Offline `.metallib` precompilation / `build.rs` (revisit only if shader
  compile-time becomes a measured cost).
- Multi-device, command-buffer pooling, async dispatch, profiling hooks.
- Linux/Vulkan or any non-Metal GPU path.

## Risks

- **metal-rs API drift:** method names (`new_library_with_source`,
  `new_compute_pipeline_state_with_function`, `contents`, `wait_until_completed`)
  are confirmed against the pinned `metal` version during implementation; the
  smoke test is the proof they wired up correctly.
- **CI runner has no Metal device:** handled by design (graceful skip); the
  cost is that CI does not *continuously* prove GPU execution — the dev-box run
  in the PR description backstops it.
