# Phase 4.5 — CPU Parity: design

**Date:** 2026-06-11
**Status:** approved (design dialogue 2026-06-11)
**Scope:** new phase inserted between Phase 4 (applications & validation) and Phase 5 (GPU) in `ROADMAP.md` § 5.

## 1. Motivation

Before starting GPU work, close (or honestly explain) the wall-clock gaps between
aleph and the mainstream simulators on CPU. This is mandated by our own
performance hierarchy (CLAUDE.md: "Don't jump to GPU when CPU has unrealized
wins") and by the project goal of being no slower than the references.

The honest current picture, from our own perf reports:

| Backend | Reference | Status | Source |
|---|---|---|---|
| SV single-thread | Qiskit Aer | aleph ahead on all 4 Tier-1 (qft 0.61×, grover 0.67×, random 0.72×, ghz 0.25×) | `docs/perf/phase1.md` + qft-parity follow-up |
| SV multi-thread | Aer multi-thread | **never measured** — Phase 2 measured self-scaling only | `docs/perf/phase2.md` |
| Stabilizer | Stim | **1.64× slower** @ d=11 (≤2× AC met; not parity). Known deferred levers: transpose ~30% + `zero_row`/`copy_row` ~33% of cycle | `docs/perf/surface_code.md` (P3-11) |
| MPS | Aer `matrix_product_state` | **never measured**; open perf tickets #148–150 | — |

So there is exactly one *known* gap (Stim) and two *unknown* cells. The phase
therefore starts with measurement, not tuning.

## 2. Exit criterion

**Every cell of the competitive matrix ≤ 1.2× the reference wall-clock**, or a
documented structural exception: profiling evidence ("here is the breakdown,
the gap is X, it is an architectural property of the reference, not an
unexploited hot spot") plus a deferred ticket. "Didn't manage" is not an
acceptable cell verdict; "N×, cause, evidence" is.

Overshooting (beating the reference) is welcome wherever it comes cheap, but
1.2× is the bar that gates the phase.

**Publication gate:** v0.2 tag and PyPI publication (P4-09, #142) are triggered
by phase completion — not before. Fresh benchmark numbers go into the v0.2
release notes.

## 3. Competitive matrix (P4.5-01)

All measurements on the EPYC 8124P box (self-hosted runner host), idle-verified
per CLAUDE.md ("uptime ≈ 0, `pgrep -af 'cargo bench|bencher run|Runner.Worker'`
clean") — we have been burned by CI races twice. Toolchain, library versions,
and exact configurations pinned in the report.

| Row | aleph side | Reference side | Workloads |
|---|---|---|---|
| SV multi-thread | `run_optimized`, 16 threads | Aer statevector method, 16 OMP threads, **default settings on both sides** (Aer's default gate fusion stays on; we document this explicitly) | Tier-1 fixtures @ n=25 from the P1-14 harness (`report.py`): ghz, qft, random brickwall; grover as an **iteration-capped** variant (full grover-25 is ~13 CPU-h single-thread — P2-05 lesson) |
| MPS | aleph-mps defaults | Aer `matrix_product_state` | brickwall n=100 (P3-10 demo circuit), long-range circuit (P3-09 bench), and the χ-sweep stress circuit from `docs/perf/mps_parallel.md` (P3-09). **Comparison gated on equal fidelity, not on nominally equal truncation settings** — truncation semantics differ between implementations; report a fidelity proxy (cumulative truncation error; exact overlap on sizes where SV validation is tractable) and match it |
| Stabilizer | dual-orientation tableau backend | Stim `TableauSimulator` | imported as-is from `docs/perf/surface_code.md` (d=3..11, 1.64× @ d=11, Stim 1.16.0) — no re-measurement unless P4.5-02 lands |

Protocol: medians over fixed run counts, both sides on the same physical box in
the same session, same circuits byte-for-byte (QASM fixtures where applicable).
Harness: extension of the P1-14 `report.py` (the uv/py3.12 venv with qiskit-aer
is already provisioned on the box).

Deliverable: `docs/perf/parity.md` — baseline columns, per-cell verdict against
the 1.2× bar, and the gap list that scopes P4.5-06. This is the phase's living
document; P4.5-07 finalizes it.

## 5. Escalation ladder (when a cell won't close)

Per-cell procedure, following the CLAUDE.md ROI hierarchy:

1. Profile (flamegraph / `perf stat`) — never tune blind.
2. Algorithm-level change.
3. Memory layout.
4. SIMD.
5. Threading.

If the gap survives the ladder and the cause is structural (e.g., Stim's fully
bit-packed architecture as a whole, rather than one unexploited hot spot), the
cell closes with a verdict: ratio, cause, evidence, deferred ticket.

**Timebox:** one PR cycle per lever. A lever whose improvement on its target
cell does not clear criterion's confidence interval (i.e., is indistinguishable
from noise) is recorded as a negative result and we move on —
precedent: P2-04's honest "no headroom" report. This is the guard against
tuning forever ("до посиніння").

## 6. Correctness and measurement-fairness risks

New correctness surface is small: P4.5-02..05 are perf changes under existing
oracle/property tests (Stim oracle d=3..11, MPS↔SV light-cone validation,
thread-count invariance). Standard testing requirements (unit + property +
oracle + before/after criterion numbers in the PR) apply unchanged.

Fairness risks, handled explicitly:

- **Aer's default fusion is on.** We compare default-vs-default (production
  config on both sides) and say so in the report.
- **MPS truncation semantics differ** between aleph and Aer. Equal-fidelity
  gating (above), not equal-named-knobs.
- **CI races on the EPYC box** silently inflate baselines. Idle verification is
  mandatory before every measurement session.
- **Iteration-capped grover** is reported as such — no extrapolation to the
  full circuit.

## 7. Out of scope

- Additional references (quimb, ITensor, pennylane-lightning) — Aer + Stim are
  sufficient for the "no worse than mainstream" goal; each extra reference is a
  new toolchain and dependency burden. Rejected during design.
- GPU work (Phase 5, issues #47–54) — untouched, starts after this phase.
- Renumbering existing P5/P6 issues — the new phase is inserted as "4.5"
  precisely to avoid that churn.
- P4-10..12 (#143–145) remain ordinary post-v0.1 backlog items, not phase
  gates; P4-09 (PyPI) is explicitly sequenced behind P4.5-07.
