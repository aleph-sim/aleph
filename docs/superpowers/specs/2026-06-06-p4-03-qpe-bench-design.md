## The circuit

Standard textbook QPE (Nielsen & Chuang §5.2) on a single-qubit unitary.

- Total qubits `n`; counting register = qubits `0..m` where `m = n − 1`; target
  qubit = index `m`.
- Unitary `U = P(2πφ)` (single-qubit phase gate). `P(θ)|1⟩ = e^{iθ}|1⟩`, so |1⟩
  is an eigenstate with eigenphase `φ = θ/2π`.
- **Eigenphase `φ = (2^m − 1) / 2^m`** — all `m` fractional bits set; exactly
  representable in the `m`-bit counting register.

Construction (`build_qpe(n)`):

1. `X` on the target qubit → eigenstate |1⟩.
2. `H` on every counting qubit `0..m`.
3. For `j` in `0..m`: `CP(2π·φ·2^j)` with control = counting qubit `j`, target =
   the target qubit. This is controlled-`U^(2^j)`; with the target held in |1⟩ the
   phase `e^{2πiφ·2^j}` kicks back onto the control's |1⟩ branch.
4. Inverse QFT on the counting register (Qiskit `QFT(m, inverse=True)`).

Built in Qiskit, transpiled to `BASIS_GATES` at `optimization_level=0`, exported
as QASM3. `CP` decomposes to `p` + `cx`; all in the existing basis the
`aleph-parser` already supports. No measurements — the corpus is a state-prep
circuit, matching the QFT/Grover convention (oracle compares full state vectors).

### Why the all-ones eigenphase

Because `φ` is an exact dyadic with all `m` bits set, QPE produces a delta: the
counting register reads the integer `2^m − 1` (every counting qubit = 1) with
probability 1, and the target stays |1⟩. The **full** state is therefore |1…1⟩,
i.e. amplitude index `2^n − 1`.

That index is invariant to:
- qubit ordering (ADR 0004 MSB-first) — all-ones maps to all-ones under any
  permutation;
- the inverse-QFT swap convention — all-ones is a bit-reversal palindrome.

So the accuracy oracle reasons about no bit layout at all: assert that amplitude
`2^n − 1` carries ≈ all the probability and is the argmax. (Sanity-checked by
hand for `m=1`: `φ=1/2`, `CP(π)` then `H` on the lone counting qubit yields |11⟩
= index 3 = `2^2 − 1`.)

## Sizes

`FAMILY_SIZES["qpe"] = [10, 15, 20, 25]`, so `m = {9, 14, 19, 24}` counting
qubits + 1 target. Gate count is O(m²) (the inverse QFT dominates), comparable to
the QFT family. `n=25 ⇒ 512 MiB` state vector — every size fits a **committed**
corpus (no gitignore needed, unlike Grover-16's 34 MB blob).

### `benches/benches/phase4_qpe.rs`
Mirror `phase4_qft.rs`: criterion group `phase4_qpe`, `SMALL_N = [10,15,20,25]`,
`sample_size(10)`, reads `qpe_n{n}.qasm`, runs `run_optimized` on
`NaiveSvBackend::with_seed(0).with_qubit_cap(32)`. No `scaling-bench` tier — 25 is
the ceiling and already lives in QFT's always-on `SMALL_N`. Register `[[bench]]
name = "phase4_qpe", harness = false` in `benches/Cargo.toml`.

### `benches/tests/qpe_accuracy.rs`
For each `n`, parse the corpus, run the **verbatim** `run` path on
`NaiveSvBackend`, and assert:
- `amps[2^n − 1].norm_sqr() > 0.999` (exact recovery; FP rounding only), and
- `argmax(|amps|²) == 2^n − 1` (amplified the right state).

`n = 10, 15, 20` run in fast CI (≤ ~1 s each). **`n = 25` is `#[ignore]`d** for
the nightly ignored-tests schedule — verbatim single-thread at 512 MiB is tens of
seconds, brushing the CLAUDE.md 30 s rule. (Corpus is committed, so no
present-on-host skip guard is needed.)

### `scripts/qiskit-baseline/test_run.py`
Add QPE assertions: `corpus_stem("qpe", 20) == "qpe_n20"`,
`workload_key("qpe", 20) == "qpe_n20"`, `FAMILY_SIZES["qpe"] == [10,15,20,25]`.

## EPYC measurement (single-thread both sides)

Same workflow as the Grover worked example in `scripts/bench-report/README.md`,
appended to the already-measured QFT+Grover JSONs (re-timing those costs hours).
QPE needs **no `oneshot` split** — all 4 sizes are criterion-feasible
(n=25 ≈ 14 s/run, like QFT-25's 10-sample criterion).

1. Idle-box check (`uptime` ~0, no `cargo bench`/`bencher run` in `pgrep`) per
   [[feedback-check-server-clean]].
2. Aer: `taskset -c 0 .venv/bin/python run.py --workloads
   qpe_n10,qpe_n15,qpe_n20,qpe_n25` → `results-qiskit.json`; merge its `qpe` rows
   into `docs/perf/data/phase4-aer.json`.
3. aleph: `RUSTFLAGS="-C target-cpu=native" RAYON_NUM_THREADS=1 cargo bench -p
   aleph-benches --bench phase4_qpe`; `extract_criterion.py --group phase4_qpe
   --family qpe` → temp; merge into `docs/perf/data/phase4-aleph.json`.
4. Update `phase4-meta.json` notes (append QPE methodology line).
5. Re-render: `report.py` → `docs/perf/phase4.md`. The QPE section appears
   automatically, sorted after Grover/QFT (alphabetical by family).
6. Add a short "Adding QPE" note to `scripts/bench-report/README.md`.

EPYC ops per [[phase4-status]]: cargo at `~/.rustup/toolchains/.../bin` (NOT on
PATH); git-bundle transfer; pin qiskit 1.2.4 / aer 0.15.1; single nohup driver
polling `until DONE`. Open the PR only **after** numbers are committed (PR
triggers CI + Bench on the shared runner).

## Out of scope (YAGNI)

- No aleph-side QPE builder (the bench/test read the corpus QASM, like Grover).
- No measurement instructions in the corpus (state-vector oracle).
- No new IR passes or kernels.
- No `scaling-bench`/`oneshot` tier (n≤25 is criterion-feasible).
