# [P5.5-03] 2q / diagonal / multi-controlled FP32 Metal kernels — Design

**Issue:** #173 · **Milestone:** Phase 5.5 — Apple/Metal GPU · **Depends on:** P5.5-02 (#172, merged `d0815b7`)

## Goal

Extend `MetalSvBackend` (device-resident FP32 statevector) from 1q-only to the full
Tier-1 gate surface so GHZ, QFT, Grover, and random circuits run on the Metal GPU —
on both the **raw** run path (`run`) and the **optimized** run path (`run_optimized`,
which emits fused `UnitaryKq`, `DiagonalPhase`, and a trailing `RelabelQubits`).

## Acceptance criteria (from #173)

- [ ] GHZ, QFT, Grover, random run on `MetalSvBackend`.
- [ ] FP32 oracle vs Qiskit Aer / `NaiveSvBackend` (statevector) within 1e-5 on Tier-1;
      normalization/unitarity proptests at FP32 tol.

## Scope decisions

- **Extended scope** — also support the optimized run path (`DiagonalPhase`,
  `UnitaryKq`, `RelabelQubits`/`unpermute_state`), not just raw Tier-1.
- **Generic kernels only** — no hand-specialized CNOT/CZ/SWAP permutation kernels.
  There is no performance gate on this ticket; specialization is a later perf ticket
  if profiling justifies it. Correctness first (Golden Rule 1).

## Key insight (what we do *not* need to build)

Three Tier-1 gate classes are already handled by the shipped P5.5-02 1q kernel via its
`ctrl_mask` field:

- QFT's controlled-`Phase`: built as `GateInstance::controlled(Gate::Phase, …)` — a 1q
  gate (`M2x2`) carrying one control. Routes through `apply_1q` with `ctrl_mask` set.
- MCX / MCZ: `Gate::X` / `Gate::Z` carrying *k* external controls — also `M2x2` +
  `ctrl_mask`.

So **no separate multi-controlled kernel is required**. The genuinely missing pieces are:
a way to apply `M4x4`, `M8x8`, `UnitaryKq`, `DiagonalPhase`, and the final relabel gather.

## Gate inventory (verified against the builders)

| Circuit | Gates | Path |
|---|---|---|
| GHZ | `H`, `Cnot` | 1q ✓ ; 2q (`M4x4`) → `apply_kq` k=2 |
| QFT | `H`, controlled-`Phase` | 1q ✓ (control via `ctrl_mask`) |
| Grover | `H`, `X`, `Cz`, `Toffoli` | 1q ✓ ; 2q → `apply_kq` k=2 ; 3q (`M8x8`) → `apply_kq` k=3 |
| random brickwall | `Rz`, `Rx`, `Cnot`, `Cz` | 1q ✓ ; 2q → `apply_kq` k=2 |
| MCX / MCZ | `X`/`Z` + k controls | 1q ✓ (`ctrl_mask`) |
| optimized path | `UnitaryKq` (k=2–5), `DiagonalPhase`, `RelabelQubits` | `apply_kq` ; `apply_diagonal_phase` ; host gather |

## Architecture

Two new GPU kernels plus one host-side operation. The existing `apply_1q` kernel is
**unchanged** (already shipped + tested; it keeps 1q / MCX / MCZ / QFT-controlled-phase).

### 1. Unified generic dense kernel `apply_kq` (`shaders/sv_kq.metal`)

One kernel covers **all** of `M4x4` (k=2), `M8x8` (k=3), and `UnitaryKq` (k=2–5). This
is the fullest expression of "generic only": CNOT, CZ, SWAP, CRz, Iswap, Toffoli, CCZ,
arbitrary `Unitary2q`, and fused k-qubit blocks all flow through it.

- **Grid:** `2^(n-k)` threads. Each thread:
  1. Reconstructs its base index by inserting `k` zero bits into the compact `tid` at
     the **sorted** target bit positions (ascending), via the standard
     `i = ((i & ~mask) << 1) | (i & mask)` insertion repeated per sorted position.
  2. Skips (returns) if `(base & ctrl_mask) != ctrl_mask`.
  3. Computes the `2^k` global indices: for local `l`, `gidx[l] = base + Σ_j
     ((l >> (k-1-j)) & 1) * tbit[j]`, where `tbit[j] = 1 << q[j]` and `q[0]` is the
     **MSB** target (matches the `Unitary2q`/`Cnot` row/col convention, ADR 0004).
  4. Reads `2^k` amplitudes into a thread-local `float2 v[32]`, does the `2^k × 2^k`
     complex mat-vec, writes the `2^k` results back. (`dim = 2^k ≤ 32` for k ≤ 5.)
- **Uniform** (`set_bytes`, `#[repr(C)] GateKqMeta`): `k: u32`, `sorted: [u32; 5]`
  (ascending positions for bit-insertion), `tbit: [u32; 5]` (logical/MSB order for
  matrix indexing), `ctrl_mask: u32`, padding to a `Pod`, alignment-safe size.
  Unused `sorted`/`tbit` slots (j ≥ k) are zero and never read.
- **Matrix** in a device buffer (buffer index 1), *not* `set_bytes`: k=5 ⇒ 1024 ×
  `float2` = 8 KB exceeds the 4 KB `set_bytes` guidance, so always use a buffer — one
  uniform code path for every k. Host keeps a **reused** matrix scratch
  `DeviceBuffer<Complex<f32>>` (sized to the k=5 max, 1024 entries), refilled per gate
  via `as_mut_slice` — no per-gate allocation.
- Row-major matrix layout `M[r * dim + cidx]`, matching `GateMatrix`/`UnitaryKq` row
  order.

### 2. Diagonal-phase kernel `apply_diagonal_phase` (`shaders/sv_diag.metal`)

For the `DiagonalPhase` IR instruction (`aleph_ir::DiagonalPhase`). One thread per
amplitude `x`:

- `φ(x) = Σ_t angle_t · [∀ m ∈ conds_t : popcount(m & x) & 1 == 1]`
- `amps[x] *= (cos φ, sin φ)`.
- Condition masks fit in `uint` — `MAX_METAL_QUBITS = 28 < 32`, so the `u64` IR masks
  narrow losslessly to `u32` for the in-scope range (assert on the host that
  `dp.n_qubits <= 28`).
- **Encoding:** two small device buffers — a flat `cond_masks: [u32]` (all terms'
  conds concatenated) and per-term descriptors `terms: [{cond_offset: u32, n_conds:
  u32, angle: f32, _pad: u32}]`; uniform carries `n_terms: u32`.
- φ accumulated and `cos`/`sin` taken in f32. Term counts are small (fused diagonal
  runs), so this is well within the 1e-5 tolerance.

### 3. `unpermute_state` (host-side gather)

The default optimization pipeline ends with `RelabelQubits`; the `Backend` driver calls
`unpermute_state(perm)` to map physical-order amplitudes back to logical order. Metal
state is unified memory, so:

- Read the `f32` amplitude slice (`as_slice`, zero-copy, after the last GPU command has
  completed — every dispatch already `wait_until_completed`s).
- Gather via `aleph_core::bit_permute_buf(phys, perm)` (the shared helper, P3-15).
- Replace the state buffer with a fresh `DeviceBuffer::from_slice`.

This fires once per run; a GPU gather kernel is unnecessary (YAGNI).

## Backend wiring (`sv/backend.rs`)

- Remove the current `if matches!(UnitaryKq) || expected != 1 { UnsupportedGate }`
  guard. Intercept `Gate::UnitaryKq { k, data }` **before** `matrix()` (as the CPU FP32
  backend does — `matrix()` returns `Unrepresentable` for it), narrow `data` to f32,
  and dispatch `apply_kq(k)`.
- Extend the `match matrix` arms:
  - `M2x2` → existing `apply_1q` (unchanged).
  - `M4x4` → `apply_kq` with k=2, targets `gate.qubits[0..2]`.
  - `M8x8` → `apply_kq` with k=3, targets `gate.qubits[0..3]`.
- Keep the f64 unitarity / NaN guard (ADR 0006) for the `GateMatrix` path. `UnitaryKq`
  and `DiagonalPhase` skip it, exactly mirroring the CPU FP32 backend.
- Implement `apply_diagonal_phase` → diag kernel; implement `unpermute_state` → host
  gather. Both currently fall through to the trait's `Err` defaults.
- Compile the two new pipelines (`apply_kq`, `apply_diagonal_phase`) in `build()` and
  store them on the backend; allocate the reused matrix scratch buffer there.

## Testing

1. **On-device unit tests** (`sv/backend.rs`): CNOT, CZ, SWAP, Toffoli, CCZ, a
   2-control MCX, MCZ, an arbitrary `Unitary2q`, a small `UnitaryKq` — textbook
   basis-state results, 1e-6 tol. Each skips cleanly when no Metal device is present.
2. **Raw Tier-1 oracle** (`tests/sv_oracle.rs`, the core AC): GHZ/QFT/Grover/random via
   `run()` vs `NaiveSvBackend` at 1e-5, extending the existing 1q oracle.
3. **Optimized-path oracle** (`tests/sv_oracle.rs`): the same Tier-1 circuits via
   `run_optimized()` vs CPU optimized, exercising `apply_kq` for `UnitaryKq`,
   `apply_diagonal_phase`, and `unpermute_state`.
4. **Proptests** (per AC): normalization (‖ψ‖² ≈ 1 within FP32 tol) and unitarity over
   random circuits drawn from 1q + 2q (+ 3q) gates.
5. **Pure helper unit tests** (no device): bit-insertion index reconstruction and the
   diagonal-term encoding, so headless CI covers the index logic.

## Explicitly out of scope (YAGNI)

- Specialized CNOT/CZ/SWAP permutation kernels — no perf gate here.
- Per-gate matrix re-allocation — a reused scratch buffer is used instead.
- GPU-side gather for `unpermute_state` — host gather suffices for a once-per-run op.
- Anything > 28 qubits — the project-wide software cap binds first (`MAX_METAL_QUBITS`).

## Risks / notes

- **Index-math correctness** is the main risk (sorted-vs-logical target ordering). The
  raw + optimized Tier-1 oracles and the multi-qubit proptests pin it; pure-helper unit
  tests isolate the bit math from the GPU.
- **f32 accumulation** in the k=5 mat-vec: 32-term complex sums in f32. Tier-1 only
  reaches k≤3 raw; `UnitaryKq` k up to 5 appears post-fusion. The 1e-5 oracle tol is the
  guard; if a fused k=5 block drifts, the optimized-path oracle catches it.
- **NaN discipline (ADR 0006)** preserved on the `GateMatrix` arm; `UnitaryKq`/diagonal
  skip it consistently with the CPU FP32 backend.
