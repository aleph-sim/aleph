# P1-10 — Gate fusion pass: 2q + adjacent 1q

**Issue:** [P1-10] Gate fusion pass — 2q + adjacent 1q (BACKLOG.md)
**Depends on:** P1-09 (`Fuse1qRuns`, `aleph_ir::passes` infrastructure)
**Date:** 2026-05-29
**Status:** Approved (brainstorm)

## Goal

Add a second IR optimisation pass, `Fuse2q`, that collapses two-qubit
gates together with their adjacent single-qubit neighbours into a single
fused 4×4 `Gate::Unitary2q`. Three fusion shapes are in scope:

1. **pre-1q absorption** — 1q gate(s) immediately before a 2q gate on
   either of its qubits fold into the 4×4.
2. **post-1q absorption** — 1q gate(s) immediately after a 2q gate on
   either of its qubits fold into the 4×4.
3. **2q·2q same-pair** — two adjacent 2q gates on the *same* unordered
   qubit pair merge into one 4×4 (e.g. `CNOT·CNOT`, `RZZ`-as-CNOT-pair).

`Gate::Unitary2q(Box<[[Complex; 4]; 4]>)` already exists and is honoured
by backends — no new `Gate` variant is required.

## Non-goals

- N-qubit (≥3) block fusion. Toffoli/CCZ and friends fence fusion.
- Cost-model / DAG-based fusion (Qiskit-style). Greedy single pass only.
- Commutation-based reordering (that is P1-13).
- Downgrading a fused 4×4 back to a named cheap gate (e.g. detecting that
  a product equals CNOT). Always emit `Unitary2q` for 2q blocks. YAGNI.

## Approach — single-pass greedy block fusion

One linear pass over `circuit.instructions`. Invariant: **each qubit has
at most one open block**; a block covers 1 or 2 qubits and carries an
accumulated unitary. This mirrors the proven structure of `Fuse1qRuns`,
extended so a block may span two qubits (both qubit keys point at the same
block).

### Data structures

```rust
struct Block {
    qubits: SmallVec<[u32; 2]>,  // canonical operand order (t0, t1); len 1 or 2
    matrix: Mat,                 // M2 for a 1q block, M4 for a 2q block
    first_index: usize,          // index of the block's first instruction
    len: usize,                  // number of instructions folded in
}
```

- `blocks: Vec<Option<Block>>` indexed by `BlockId`; flushing takes the
  block (`Option::take`) and pushes its emitted instruction(s) to `output`.
- `open: HashMap<u32, BlockId>` — qubit → its open block. A 2q block
  registers both of its qubits.
- `output: Vec<Instruction>` — built separately; `circuit.instructions`
  is only replaced on success (mirrors `Fuse1qRuns`: read `&circuit.instructions`
  directly, never `std::mem::take`, so an `Err` leaves the circuit intact).

### Per-instruction handling

For each instruction, classify the gate:

- **Non-fusable** (measurement, reset, barrier, `arity() > 2`, or
  `to_matrix()` returns `Err`): flush every open block on the qubits it
  touches, then re-emit the instruction verbatim.

- **1q fusable gate on qubit `a`:**
  - If `a` has an open block `B` (1q or 2q): left-multiply `B.matrix` by
    `lift_1q(m2, a, B.qubits)`; `B.len += 1`. (This is post-1q absorption
    when `B` is a 2q block.)
  - Else: open a fresh 1q block on `a`.

- **2q fusable gate on operands `(a, b)`:**
  1. Let `Ba = open[a]`, `Bb = open[b]`.
  2. **Same-pair merge:** if `Ba == Bb` and that block's qubit set is
     `{a, b}` → left-multiply by the gate's 4×4 (reordered via
     `reorder_swap` if the block's operand order is `(b, a)`); `len += 1`.
  3. **Otherwise open a new 2q block:**
     - For `x` in `{a, b}`: if `open[x]` is a *2q* block (it cannot be a
       compatible pre-1q), flush it. After this, any block still open on
       `a`/`b` is a 1q block.
     - Collect pre-1q matrices `Ma`, `Mb` from the (now 1q) open blocks on
       `a`, `b` (identity if none); remove those blocks (consumed).
     - New block: `qubits = [a, b]` (gate's own operand order, so the
       gate's matrix needs no reorder), `matrix = G4 · (lift_1q(Ma,a) · lift_1q(Mb,b))`,
       `first_index` = the 2q gate's own instruction index (NOT min of consumed
       and own; see "Why this is correct" below), `len` = sum.
     - Register the new block as open on both `a` and `b`.

At end of stream: flush all remaining open blocks (in ascending
`first_index` order to keep output stable).

### Why this is correct

The single-open-block-per-qubit invariant guarantees that any two gates
sharing a qubit flow through that qubit's block in original order — a gate
on `q` is either folded into `q`'s open block (extending it in order) or
forces a flush of `q`'s block before being handled. Gates on disjoint
qubit sets may be emitted in either relative order without changing the
unitary, so lazy flushing is safe. No reordering of dependent gates ever
occurs.

**Ordering key for 2q blocks:** a 2q block always sorts at its 2q gate's
own index. Using `min(pre-1q.first_index, 2q_gate.index)` is WRONG and
was a correctness bug in the original implementation. The pre-1q gate on
one qubit may have a smaller index than an intervening op on the OTHER
qubit of the block. Taking the min would drag the fused block before that
intervening op, reordering a dependency. The 2q gate's own index is always
safe: pre-1q gates were only folded because there was no intervening op on
their respective qubit between them and the 2q gate; post-1q gates are
folded after the 2q gate's position. Therefore keying at the 2q gate's
index places the block after all instructions that preceded its run on
either qubit and before all instructions that follow. **Fuse2q is correct
standalone — it does not depend on Fuse1qRuns having run first.**

## Matrix algebra (P0-06 / ADR 0004 convention — VERIFIED against the kernel)

**Ground truth** (`aleph-sv` `apply_2q_dense_scalar`, kernels/aos.rs:1208):
for a 2q gate with operands `targets = [qubits[0], qubits[1]]`, the 4×4
matrix index `k ∈ 0..3` maps **bit 1 (MSB of k) → qubits[0]**, **bit 0
(LSB of k) → qubits[1]**. I.e. `k = (qubits[0]_val << 1) | qubits[1]_val`
— **qubits[0] is the high matrix bit, qubits[1] the low bit.** (This is
the opposite of a naive "operand 0 = LSB" reading; verified against the
kernel that the oracle tests pin to Qiskit.)

Block canonical operand order therefore is `block.qubits = [hi, lo]` =
the opening 2q gate's `[qubits[0], qubits[1]]` verbatim — so the opening
gate's own 4×4 needs **no** reordering.

Helpers local to `fuse_2q.rs` (decompose index `k` as `hi=(k>>1)&1`,
`lo=k&1`):

- `lift_1q(m2, q, block_qubits) -> [[Complex;4];4]`, `block_qubits=[hi,lo]`:
  - `q == block_qubits[0]` (hi / MSB): `out[r][c] = m2[hi_r][hi_c] · δ(lo_r,lo_c)`
  - `q == block_qubits[1]` (lo / LSB): `out[r][c] = m2[lo_r][lo_c] · δ(hi_r,hi_c)`
- `reorder_swap(m4) -> [[Complex;4];4]`: `out[r][c] = m4[swap2(r)][swap2(c)]`
  where `swap2(x) = ((x & 1) << 1) | ((x >> 1) & 1)`. Re-expresses a 4×4
  given in operand order `(a,b)` into order `(b,a)`. Used when an incoming
  same-pair 2q gate's operand order is the reverse of the block's. Applying
  it twice is the identity.
- `mul4(a, b) -> [[Complex;4];4]`: plain 4×4 product (local; `aleph_core`'s
  `mul4` is private). Composition direction: a gate applied later is
  **left-multiplied**: `new = mul4(&lift(G), &block.matrix)`, consistent
  with `state' = G·(prev·state)`.
- Pre-1q on open: `block.matrix = mul4(&G4, &mul4(&lift_1q(Ma,a), &lift_1q(Mb,b)))`
  (`Ma`, `Mb` on disjoint bits commute; product order is irrelevant).

### Emission

- **2q block** (`qubits.len() == 2`): `Gate::Unitary2q(Box::new(m4))` with
  operands `block.qubits.clone()` = `[hi, lo]` (the opening gate's operand
  order, matching the m4's convention). Always emit
  even if `len == 1` is impossible for a 2q block (a 2q block is only ever
  created from a 2q gate, so `len ≥ 1`; if `len == 1` and no 1q folded, the
  matrix equals the original gate — still emit `Unitary2q`; no count change,
  no `transformations++`).
- **1q block:** `len == 1` → re-emit the original instruction verbatim
  (preserves named/`Diag` gate). `len > 1` → `Unitary1qDiag` if diagonal
  within tolerance, else `Unitary1q` (same diag-detection threshold as
  `Fuse1qRuns`). In practice, with `Fuse1qRuns` running first, 1q blocks
  here are almost always `len == 1`.

### transformations / stats

`transformations` counts blocks whose `len ≥ 2` (i.e. an actual
fold/merge happened — gate count strictly decreased for that block).
`gates_before = input.len()`, `gates_after = output.len()`.

## Pipeline wiring

`PassPipeline::default_pipeline()` becomes:

```rust
Self::new(vec![Box::new(Fuse1qRuns), Box::new(Fuse2q)])
```

Order matters: `Fuse1qRuns` collapses 1q runs to single gates first, so
`Fuse2q` sees at most one 1q gate per qubit between fences and folds it
into the neighbouring 2q. `Fuse2q` would handle 1q runs itself, but the two
passes stay separate for diff size, separation of concerns, and the
`Unitary1qDiag` specialisation P1-09 owns.

## Fusable predicate

A gate is fusable iff `arity() ∈ {1, 2}` **and** `to_matrix()` returns
`Ok` **and** it is not a measurement / reset / barrier. Controlled 2q
gates (`Cnot`, `Cz`, `Swap`, `Iswap`, …) have a 4×4 matrix and are
fusable. `arity() ≥ 3` (Toffoli, CCZ, MCX) fences fusion. Measurement,
reset, and barrier fence fusion on the qubits they touch.

## Error handling

The pass is infallible in practice (like `Fuse1qRuns`) and returns `Ok`.
Any gate that cannot be turned into a matrix is treated as non-fusable and
re-emitted verbatim — never a panic, never an `Err`. `PassError::InternalInvariant`
remains reserved for a genuine internal contradiction (e.g. a registered
block id missing from `blocks`).

## Testing

Per CLAUDE.md: unit + property + oracle + benchmark.

### Unit (`mod tests` in `fuse_2q.rs`)

- pre-1q: `Rx(θ,0); CNOT(0,1)` → one `Unitary2q`, count 2→1.
- post-1q: `CNOT(0,1); Rz(θ,1)` → one `Unitary2q`, count 2→1.
- 2q·2q same pair: `CNOT(0,1); CNOT(0,1)` → one `Unitary2q` (≈ I).
- reversed operand order: `CNOT(0,1); Cz(1,0)` exercises `reorder_swap`.
- disjoint-qubit op does not block a same-pair merge:
  `CNOT(0,1); H(2); CNOT(0,1)` → the two `CNOT`s merge into one
  `Unitary2q` (nothing on `{0,1}` between them) and `H(2)`, on a disjoint
  qubit, is preserved in the output.
- intervening op on a shared qubit folds rather than fences:
  `CNOT(0,1); H(0); CNOT(0,1)` → `H(0)` folds into the first block
  (post-1q), the second `CNOT` then same-pair-merges → one `Unitary2q`.
- hard fence on a shared qubit blocks the merge: `CNOT(0,1); measure(0);
  CNOT(0,1)` → two `Unitary2q` blocks survive with the measurement between.
- hard fences: `barrier`, `measure`, and a Toffoli between two 2q gates on
  the same pair each prevent the merge; assert two blocks survive.

### Property (`proptest!`)

On random small circuits (reuse `aleph-test` strategies):
1. **Equivalence:** state vector of fused circuit ≡ unfused within 1e-12.
2. **Monotonicity:** `gates_after ≤ gates_before`.
3. **Idempotence:** running `Fuse2q` a second time does not reduce the
   gate count further (blocks are maximal after one pass).

### Oracle / equivalence

Mirror P1-09's multi-fixture oracle: run each fixture unfused and fused
through a backend and compare amplitudes within 1e-12. Corpus: Bell, GHZ,
QFT, VQE-HEA, QAOA, random.
