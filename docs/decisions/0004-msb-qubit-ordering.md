# ADR 0004 — MSB qubit ordering convention

**Status**: Accepted (2026-05-25, retroactive)
**Issues**: [P0-06](../../BACKLOG.md), [P0-09](../../BACKLOG.md)

## Context

Every state-vector simulator must fix a convention mapping
"basis state amplitude index" to "per-qubit bit value".  Two
choices are mutually exclusive and either works in isolation,
but **any code that touches the state vector must agree** —
backend kernels, measurement primitives, oracle comparisons,
parser/emitter, CLI output formatters.

Three Phase-0 sub-areas had to lock down this convention before
they could ship:

* `aleph-core::Gate::Unitary2q` (P0-06): the 4×4 matrix
  entries need a defined `(target₀, target₁)` interpretation.
* `aleph-sv` kernels (P0-09): `apply_1q`, `apply_2q`, `apply_3q`
  walk amplitudes via bit-mask indexing — the bit positions for
  `target₀` / `target₁` / `target₂` must match the gate matrix.
* CLI output and oracle harness (P0-11, P0-12): basis labels
  printed as `|q_{n-1}…q_0⟩` must read the same way the backend
  computed them.

If a later backend (MPS, stabiliser, GPU) reaches a different
conclusion, the oracle harness will produce nonsense diffs and
the bug will look like a kernel issue, not a convention issue.

## Decision

**`amps[i]` corresponds to the basis state whose qubit `q` has
value `(i >> q) & 1`.  Equivalently: qubit 0 is the LSB of the
amplitude index, qubit `n-1` the MSB.**

For multi-qubit gate matrices:

* 1-qubit gate `U` on qubit `q`: `amps[i]` and `amps[i ⊕ (1<<q)]`
  are paired in the kernel; the 2×2 matrix multiplies the column
  `[amps[i_q=0], amps[i_q=1]]ᵀ`.
* 2-qubit gate `U` on qubits `t₀, t₁` (e.g. CNOT control=t₀,
  target=t₁): the 4×4 matrix indexes by `(t₁_bit << 1) | t₀_bit`
  — **target₀ is the least-significant matrix index, target₁ the
  most-significant**.  CNOT's matrix is therefore
  `diag(1, 1, 0, 0) + offdiag(0↔1 at t₀=1)`, with t₀ being the
  control.

This matches Qiskit's "little-endian qubit ordering"
([Qiskit docs](https://qiskit.org/documentation/intro_tutorial1.html#bit-ordering))
which is **why** the oracle harness sees agreement on every
fixture.

## Consequences

* Counts output prints `|q_{n-1}…q_0⟩` (e.g. `|11⟩` means
  q₁=1, q₀=1 for a 2-qubit state).  The CLI's
  `format_counts` formats indices with `{:0width$b}` — that
  prints the MSB on the left, matching the convention.
* Qiskit fixtures generated by `oracle/gen.py` need no
  reindexing: Qiskit's default endianness is little-endian on
  qubits, same as ours.
* **MPS / stabiliser / GPU backends MUST follow this
  convention** when they land in Phase 3 / 5.  The oracle
  harness will catch violations on day one but the diff message
  may not be obvious — flag this ADR in those crates' design
  specs.

## Alternatives considered

* **Big-endian qubit ordering** (qubit 0 = MSB of amplitude
  index).  Used by IBM's pre-Qiskit-Terra software stack and by
  some textbooks.  Rejected because Qiskit Aer (our oracle) uses
  little-endian; matching it removes an entire class of
  fixture-translation bugs.

* **Per-circuit choice via a flag**.  Rejected — every site
  that touches the state vector would need to thread the flag
  through, and a single mismatched site causes silent
  wrong-answer bugs.  One convention, locked down at the type
  level.
