# P5.11-03 — amortise PCIe over multi-gate tile residency

The out-of-core paged executor (P5.10-02, `CudaSvBackend::run_paged`) streams the
whole `2^n` state through PCIe **once per gate** — one read + one write of the
full state for *every* gate, regardless of which qubits it touches. That is
bandwidth-optimal per gate but wasteful across a circuit: PCIe traffic scales with
the gate count.

P5.11-03 adds `CudaSvBackend::run_paged_batched` (+ an FP32 mirror on
`CudaSvBackendF32`): a run of consecutive gates that touch **only low (within-tile,
`< m`) qubits** is applied to each tile *while it is resident* — load the tile
once, apply the whole run on-device, scatter once — collapsing `L` per-gate PCIe
passes into **one**. For locality-rich circuits (1q layers, nearest-neighbour 2q
on low qubits) this is the single largest paging lever.

## Why it is exact

Tile `T` holds the `2^m` amplitudes whose high bits equal `T` and whose low bits
range over `0 .. 2^m`. A gate on low qubits only mixes amplitudes that differ in
low bits, so it never crosses a tile boundary: applying it to tile `T`'s
sub-state as an `m`-qubit gate is identical to applying it over the whole state.
A *sequence* of low-only gates preserves this, so the entire run can run on the
resident tile. Gates touching any high qubit need co-resident tile groups, so they
**flush the current run** and fall back to the proven per-gate `apply_gate_paged`
path. The arithmetic per amplitude is the same kernel in the same order either
way, so the batched state is **bit-for-bit equal** to per-gate paging.

## Scheduling

`run_paged_batched` walks the circuit accumulating a maximal run of low-only gates
(barriers carry no state, so they neither break a run nor cost a pass). On a
high-qubit gate it flushes the run (one resident pass over all `2^(n-m)` tiles),
then applies the high gate per-gate. `paged_pass_counts(circuit, m)` reports the
`(per_gate, batched)` full-state pass counts analytically — per-gate = gate count;
batched = number of (low-run ∪ high-gate) segments. No qubit relabelling yet (the
ticket lists it as optional); the lever already pays on circuits whose hot qubits
are naturally low.

## Correctness

`tests/paged_batched_oracle.rs`: forced-tiled at small `n`, the batched state is
**bit-for-bit equal to both the CPU `NaiveSvBackend` and the per-gate `run_paged`**
at 1e-10, across `ghz` (no low runs — batched == per-gate), `qft` (mixed
high/low), and locality-rich circuits, over tile splits `h ∈ {1,2,3}`. A
GPU-free pass-count unit suite (`sv::paged::tests`) pins the schedule logic. All
pass.

## Throughput

A/B on the RTX 4000 SFF Ada (`openwebgui.splynx.com`, 20 GiB, idle GPU), same
locality-rich circuit (per layer: 1q rotations on every low qubit + a NN CNOT
brick within the low block = one long low-only run, then one CNOT crossing into a
high qubit), run out-of-core both ways. `tile_qubits = m = split`, so each layer's
low run folds into a single resident pass and only the cross-block CNOT stays
per-gate. (release build, best of `reps`):

| n  | depth | gates | per-gate passes | batched passes | passes ↓ | per-gate | batched | speedup |
|----|-------|-------|-----------------|----------------|----------|----------|---------|---------|
| 30 | 2     | 100   | 100             | 4              | **25×**  | 279.5 s  | 86.1 s  | **3.25×** |
| 31 | 1     | 52    | 52              | 2              | **26×**  | 297.7 s  | 30.0 s  | **9.93×** |

PCIe traffic drops 25–26× (the acceptance metric is ≥2×). Wall-time improves
3.25–9.93×: once PCIe is no longer the bottleneck, the **unfused residency
compute** (every low gate launched per tile, e.g. 51 gates × 32 tiles) becomes the
new floor — which is exactly where IR fusion stacks (a low run can be fused into
`UnitaryKq` blocks before the residency apply; noted as composable in the ticket
and orthogonal to P5.11-02's copy-overlap). The n=31 depth-1 case (one long run
amortised against a single high gate) shows the lever's headroom: ~10×.

## Verdict

Multi-gate tile residency cuts out-of-core PCIe traffic by the run length — 26×
fewer full-state passes and **9.93× wall-time at n=31** on a locality-rich circuit
— while staying oracle-exact. It is exposed as `run_paged_batched` (FP64 + FP32);
the per-gate `run_paged` remains the A/B baseline. It composes with IR fusion
(cheaper residency compute) and with `run_paged_overlapped` (copy/compute overlap)
for further gains.
