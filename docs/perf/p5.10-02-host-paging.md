# P5.10-02 — host-memory paging for n > 30 (out-of-core single-GPU SV)

`MAX_CUDA_QUBITS = 30` is the largest state that fits the 20 GiB RTX 4000 Ada
(16 GiB of FP64 at n=30). P5.10-02 lifts that ceiling: hold the `2^n` state in
**pinned host memory** and stream device-sized `2^m` tiles through the GPU, one
gate at a time, so n=31+ runs on a single card at a bandwidth-bound cost.

## Tiling scheme

Split the `n` qubits into `m = tile_qubits` **low** bits (a tile is `2^m`
contiguous amplitudes) and `h = n − m` **high** bits (which tile). A dense gate's
output at each amplitude depends only on the *values* of the amplitudes it pairs,
never on the absolute index — so any unitary gate can be applied tile-locally
after bringing its paired amplitudes co-resident:

- A gate touching `hh` **high** qubits needs its `2^hh` tiles (varying those
  high bits) co-resident. They are gathered into one device buffer at offsets
  `s·2^m`, so device-local bit `m + rank` ↔ the gate's high qubit `H[rank]`;
  low qubits map to themselves.
- The gate is then a normal `(m + hh)`-qubit gate on that buffer, applied by
  **reusing the in-core kernels** (`apply_1q` / `apply_cnot` / `apply_kq` /
  diag) with its qubits/controls remapped — then the tiles scatter back.

Iterating the `2^(h − hh)` outer combinations covers the whole state in exactly
one read + one write per gate (bandwidth-optimal). Diagonal-phase / tiled-block
instructions read the global index and are rejected; the caller passes an
unfused gate circuit (`run_paged`).

## Correctness

`tests/paged_oracle.rs` forces paging on at small `n` with small tiles (so the
high/low split and the cross-tile gather are genuinely exercised) and pins the
final state **bit-for-bit against the CPU `NaiveSvBackend` at 1e-10**, across:
tile sizes `h = n − m ∈ {1,2,3}`; GHZ, QFT (controlled phases ⇒ many high↔high
hh=2 pairs), and random brickwall; and a tiny n=4/m=2 high–high CNOT worst case.
Plus a norm≈1 check at n=12. (`compose_high` has its own unit test.)

## Benchmark (RTX 4000 SFF Ada, 20 GiB, FP64)

### 1. Throughput hit vs in-core (equal n)

Same circuit, in-core (resident) vs paged (forced, streaming), at n that fits
both ways — the ratio is the pure cost of moving the state over PCIe instead of
keeping it on the card.

```
== P5.10-02 paged vs in-core, n=28, 55 gates, best of 3 ==
in-core:           2.0998s
paged m=25 (h=3): 38.8528s  (18.50× in-core)
paged m=23 (h=5): 38.8133s  (18.48× in-core)
```

The hit is **~18.5×**, and **independent of tile size** (h=3 vs h=5 tie): every
gate moves the whole state to the device and back regardless of how finely it is
tiled, so the cost is fixed PCIe traffic, not per-tile overhead. The ratio is
fundamental — PCIe (~12 GB/s effective here) vs the card's resident memory
bandwidth (~360 GB/s) — so paging is a **reach** lever (run what otherwise can't
run), not a speed lever. The kernel compute is negligible next to the transfer.

### 2. Reach: n=31 (impossible in-core)

n=31 is 32 GiB of FP64 — larger than the 20 GiB card — and runs only via paging.

```
== P5.10-02 reach: n=31 (32 GiB FP64), tile m=26 ==
total 177.03s, 31 gates, 5.711s/gate
effective host↔device throughput: 12.0 GB/s
norm = 1.000000 (want ≈ 1)
```

n=31 runs out-of-core on the 20 GiB card and stays exactly normalised — each gate
streams 64 GiB (read + write) at ~12 GB/s ⇒ ~5.7 s/gate.

**n=32** would need 64 GiB of pinned host RAM; this box has 62 GiB total, so n=31
is the reachable ceiling *here*. The code path is n-agnostic — n=32/33 run given
enough host RAM.

## Findings & follow-ups

- Reach achieved: n=31 runs out-of-core on a 20 GiB card, oracle-correct
  (norm ≈ 1), at a documented bandwidth-bound cost.
- The current copies are **stream-ordered and synchronous**: cudarc inserts a
  host sync whenever a borrowed slice backs an async copy, so H2D, compute, and
  D2H do not yet overlap. The state buffer is pinned, so each copy is still fast
  pinned DMA — the loss is only the lack of overlap, not copy speed.
- **Follow-up (true double-buffering):** issue the copies via raw-FFI async
  (`memcpy_htod_async`) on a dedicated copy stream with two device tile buffers,
  so gather(i+1) / compute(i) / scatter(i−1) overlap. Expected to recover most of
  the paged-vs-in-core gap, since the gate compute and the PCIe transfer are then
  concurrent. Tracked as a P5.10-02 optimization follow-up.
