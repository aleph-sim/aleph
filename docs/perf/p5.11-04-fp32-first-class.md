# P5.11-04 — first-class FP32 backend: GPU-resident readout + throughput levers

`CudaSvBackendF32` (P5.10-03) shipped as a per-gate apply path with host-side
amplitude readout only — not a `Backend` impl, and without the Phase 5.9 / 5.10-01
throughput levers. P5.11-04 makes it a **drop-in first-class backend** whose
throughput wins **stack on the 2× precision win**.

## What was ported

- **Full `Backend` trait impl** — `allocate` / `apply_gate` / `measure` / `sample`
  / `expectation_value` / `probabilities` / `apply_diagonal_phase`. The inherent
  `apply_gate` worker stays (used by `run` and the paged executor); the trait
  delegates to it.
- **GPU-resident readout** — `GpuReadoutF32` + `readout_f32.cu`, the f32-amplitude
  mirror of `GpuReadout`: the reduction kernels read `cplxf` amplitudes but
  **accumulate in `double`**, so only a scalar / `2^k` marginal / `shots` indices
  cross PCIe (the `2^n` state stays on the device). The norm-drift budget is FP32's
  (`1e-3` relative) — the FP64 `√n·1e-10` budget would reject every FP32 state.
- **Apply-side levers** — three new FP32 kernels in `kernels_f32.cu`:
  `apply_1q_multi_f32` (disjoint-1q-layer batching via `run_layered`),
  `apply_phase_poly_f32` (fused diagonal-phase polynomials for QFT/QPE; `phi`
  accumulated and `sincos`'d in double, folded into the float amplitude), and
  `apply_kq_tiled_f32` (warp-cooperative register-tiled fused-block matvec, the
  k≥`tiled_min_k` route — the float matrix tile lives in shared memory at half the
  bytes of FP64). CNOT-permutation routing is gated on `custom_2q` as in FP64.
- **IR fusion is precision-agnostic** — `fuse_for_gpu` operates on the IR, not
  amplitudes, so the FP32 backend reuses it unchanged; its passes feed the new
  phase-poly / tiled-block kernels.

The config flags (`custom_2q` / `tiled_kq` / `tiled_min_k` / `layer_batch` /
`custom_diag`) and `with_seed` match the FP64 backend, so the A/B benches are
precision-symmetric.

## Correctness

All on the RTX 4000 SFF Ada, vs the exact FP64 CPU `NaiveSvBackend`:

- **`tests/fp32_readout_oracle.rs`** — expectation + marginal probabilities within
  **1e-5** (worst **7.2e-7** across n=2..8, X/Y/Z Paulis and qubit subsets);
  measurement pinned by GHZ correlation + a valid collapsed basis state; sampling
  matches the exact distribution at 400k shots and is seed-reproducible. ✅ 3/3
- **`tests/fp32_layer_oracle.rs`** — `run_layered` is **bit-identical** to per-gate
  `run` (Δ=0) and within 1e-5 of CPU; IR-**fused** QFT (Δ=3.7e-9) and brickwall
  (Δ=3.1e-8) through the trait match CPU — exercising `apply_phase_poly_f32` and
  `apply_kq_tiled_f32`. ✅ 2/2
- **`tests/fp32_oracle.rs`** (regression) — per-gate Tier-1+2 worst **6.2e-8**. ✅

## Verdict

The FP32 backend is now first-class: the same GPU-resident readout and apply-side
throughput levers as FP64, oracle-equal within 1e-5, with the lever wins stacking
on the 2× precision/bandwidth win.
