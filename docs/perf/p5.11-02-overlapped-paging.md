# P5.11-02 — overlapped (double-buffered) paging copies

The out-of-core paged executor (P5.10-02, `CudaSvBackend::run_paged`) streams the
whole `2^n` state through PCIe once per gate, issuing gather → compute → scatter
**synchronously on one stream** — so the host↔device copy directions never
overlap. P5.11-02 adds `CudaSvBackend::run_paged_overlapped`: the same tiling,
but the copies are double-buffered across dedicated streams so H2D overlaps D2H
(PCIe is full-duplex) and compute hides behind the transfers.

## The hard ceiling: ~1.24×, not 2×

A direct microbench on the RTX 4000 SFF Ada (`openwebgui.splynx.com`): copying
1 GiB H2D and 1 GiB D2H **serially** on one stream reaches 12.9 GB/s aggregate;
**concurrently** on two streams (two copy engines, `async_engine_count=2`)
reaches only 16.0 GB/s. So the card's duplex link gives a **~1.24× ceiling** —
each direction throttles to ~8 GB/s when both engines are busy. Overlap is a
recover-a-fraction lever, not a doubling.

## Design

`run_paged_overlapped(circuit, tile_qubits, depth)`:

- A **ring of `depth` device tile-group buffers** (round-robin), so the H2D
  stream can run ahead of D2H. Two buffers is too shallow — the
  `gather(i) ← scatter(i−depth)` dependency forces the copy engines to
  *alternate* instead of overlap; `depth ≈ 4` keeps both busy.
- **Three streams:** gather on a non-blocking H2D stream, compute on a non-blocking
  stream (NOT the legacy default stream — that serialises against the copy
  streams), scatter on a non-blocking D2H stream. Ordering is by **explicit CUDA
  events** (compute waits gather; scatter waits compute; a buffer reuse waits its
  prior scatter; the first gather of each gate waits the previous gate's last
  scatter — the host-memory hazard).
- **Raw-FFI async copies** (`result::memcpy_{htod,dtoh}_async` against precomputed
  buffer base pointers). cudarc's *safe* `memcpy_htod`/`memcpy_dtoh` put the
  context in event-tracking mode and add per-copy bookkeeping that serialises the
  pipeline down to ~0.66×; the raw path keeps the duplex bandwidth.
- **Per-gate hybrid:** a gate with too few groups to fill the pipeline (high
  fan-out `hh`, so `n_outer < 2·depth`) can't overlap — engaging both engines
  would only pay the duplex throttle. Those shallow gates fall back to the proven
  synchronous per-gate path (`apply_gate_paged`) on the legacy default stream, at
  full per-direction bandwidth.
- The retaining memory pool is trimmed before the (large) ring is allocated, so a
  prior run's retained device blocks don't exhaust the card.

## Correctness

`tests/paged_overlap_oracle.rs`: forced-tiled at small `n`, the overlapped state
is **bit-for-bit equal to the synchronous `run_paged`** (FP64, only the scheduling
differs) and equal to the CPU `NaiveSvBackend` at 1e-10. Tile sizes span
`h ∈ {1,2,3}` and gate fan-outs hh = 0,1,2, so both the overlapped and the
synchronous-fallback paths are exercised. 3/3 pass.

## Throughput

**Methodology caveat:** this box has time-varying PCIe/clock state — the same run
reads 7 GB/s or 14 GB/s minutes apart. A single-process sync-then-overlap A/B is
therefore unreliable (it spuriously read 0.65× by catching sync in a fast window
and overlap in a slow one). The valid measurement is **interleaved, one path per
process, on a verified-idle GPU** (`tests/paged_overlap_bench.rs::paged_throughput`
driven from a shell loop).

Interleaved on the idle box (3 rounds each, fully reproducible):

| n  | sync         | overlap      | speedup |
|----|--------------|--------------|---------|
| 28 | 35.9 s (6.7 GB/s) | 32.7 s (7.4 GB/s) | **1.10×** |
| 30 | 148.4 s (6.9 GB/s) | 134.7 s (7.6 GB/s) | **1.10×** |

The ~1.10× is ≈89% of the 1.24× hardware duplex ceiling — the residual is the
shallow high-fan-out gates (synchronous fallback) and pipeline fill/drain. (Absolute
GB/s here reflect a slow box window; the *ratio* is what the interleaved A/B
isolates and it is stable.)

## Verdict

Overlap delivers a real, reproducible **~1.10×** over the synchronous paged path,
near the card's PCIe duplex ceiling, while remaining oracle-exact. It is exposed
as `run_paged_overlapped` (the synchronous `run_paged` remains the default and the
A/B baseline). Deeper wins on the out-of-core path are PCIe-bound and would need
faster host↔device hardware.
