# Phase 5.9 — CUDA SV throughput → Aer-GPU parity

Phase 5 met its exit gate (aleph FP64 GPU SV within 1.22× of cuStateVec on every
Tier-1 + Tier-2 workload), but the P5-08 report found **Qiskit Aer-GPU is 2–5×
faster than both aleph and cuStateVec** — same FP64, its own engine (not
cuStateVec), the advantage entirely **above the kernel**: gate fusion + batched
dispatch (`docs/perf/p5-08-gpu-report.md`). Phase 5.9 closes that gap. This page
tracks it; the exit metric is in `ROADMAP.md` §7.

## P5.9-01 — feed the existing IR fusion passes into the GPU path

`fuse_for_gpu()` runs the GPU-applicable fusion sub-pipeline — `CancelInversePairs`
→ `DeadCodeElim` → `Fuse1qRuns` → `Fuse2q` — before the backend. These emit
`Unitary1q` / `Unitary2q` blocks, which the CUDA backend already applies (they
carry a `GateMatrix`, unlike `UnitaryKq`). **No new kernels.** Fewer gates ⇒ fewer
full-state passes, the dominant cost at scale.

Correctness: `tests/gpu_fusion_bench.rs::gpu_fused_matches_cpu_unfused` pins the
fused GPU run against the unfused CPU `NaiveSvBackend` at 1e-10.

### Result (RTX 4000 SFF Ada, FP64, n=28, best of 4)

| workload     | gates (before→after) | unfused (s) | fused (s) | speedup | gap to Aer-GPU |
|--------------|----------------------|------------:|----------:|--------:|---------------:|
| QFT          | 406 → 406            | 10.54       | 10.54     | 1.00×   | 1.73× (unchanged) |
| random (d20) | 1100 → 540           | 49.88       | 30.37     | **1.64×** | 2.15× → **1.30×** |
| VQE (8L)     | 664 → 242            | 29.53       | 14.42     | **2.05×** | 2.89× → **1.42×** |
| QAOA (p4)    | 476 → 138            | 22.39       | 9.02      | **2.48×** | 3.42× → **1.38×** |

The free step (no new kernels) closes most of the dense-workload gap: from 2.1–3.4×
behind Aer-GPU to **1.3–1.4×**. QFT is untouched — its controlled-phase ladder is
diagonal and doesn't collapse under `Fuse1q`/`Fuse2q`; it needs the diagonal path
below.

## Remaining levers (where the rest of the gap is)

1. **Diagonal-run fusion (QFT/QPE).** `FuseDiagonalRuns` collapses a phase ladder
   into one `DiagonalPhase` instruction (a phase polynomial over ≤64 qubits). A
   GPU kernel that evaluates `amps[x] *= exp(i·φ(x))` in one sweep — building on
   the P5-06 diagonal kernels — turns QFT's ~350 cphase passes into ~1. This is
   the single biggest lever for the diagonal half (QFT is 1.73× behind on nothing
   but pass count). → **P5.9-02**.
2. **4–5q dense blocks.** `FuseKq` (default width 4) already fuses dense runs into
   `UnitaryKq`; the `apply_kq` kernel already guards `k ≤ 5`. Missing: the GPU
   backend reading `UnitaryKq.data` directly (it currently rejects `UnitaryKq`)
   and the host operand mapping for k=4,5. Shrinks the residual on random/VQE/QAOA
   below the Fuse2q result. → **P5.9-02**.
3. **Disjoint-layer single-sweep dispatch.** Apply all disjoint-qubit gates of a
   layer in one pass over the state (the SV analogue of the P5-07 `stab_layer`),
   cutting both launches and sweeps. → **P5.9-03**.
4. **Specialised 2q kernels** (CNOT permutation, diagonal-2q) for the last
   1.13–1.22× vs cuStateVec. → **P5.9-04**.
