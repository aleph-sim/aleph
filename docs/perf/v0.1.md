# aleph v0.1 — benchmark report

Consolidated performance summary for the v0.1 release. **No new measurements** —
every number below is copied verbatim from a committed per-phase report, cited
under each table; read those documents for full methodology, raw data, and
variance.

**Where aleph v0.1 stands:** on structured algorithm circuits (QFT, Grover,
QPE, VQE), aleph's state-vector backend is *faster* than single-thread Qiskit
Aer at every measured size — driven by IR-level gate fusion / diagonal-phase
passes plus AVX-512 kernels. On unstructured random circuits (Sycamore-style)
Aer's dense C++ kernels win by 3–5×. The stabilizer backend matches Stim's
results exactly on surface-code syndrome extraction and is within 2× of Stim's
speed at distance 11 (faster below d=7). The MPS backend runs a validated
128-qubit shallow circuit in ~10 ms.

**Reference box:** AMD EPYC 8124P (16c/32t, Zen 4c, AVX-512), Ubuntu,
`RUSTFLAGS=-C target-cpu=native`. **Single thread on BOTH sides** unless stated
otherwise; full host/toolchain detail in the per-phase documents linked in each
section.

## 2. Stabilizer backend vs Stim (surface code)

One rotated surface-code syndrome-extraction cycle (2d²−1 qubits), aleph
`StabilizerBackend` (CHP tableau, O(n²)) vs Stim 1.16.0 `TableauSimulator`,
single-thread both sides. Numbers below are the current (post-P3-11
word-parallel-gates) table; correctness is gated by postselected
stabilizer-group equivalence vs Stim at every d.

| d | qubits | aleph (ms) | Stim (ms) | aleph / Stim |
|--:|-------:|-----------:|----------:|-------------:|
| 3 | 17 | 0.003 | 0.008 | 0.40× |
| 5 | 49 | 0.011 | 0.013 | 0.81× |
| 7 | 97 | 0.037 | 0.023 | 1.63× |
| 9 | 161 | 0.092 | 0.056 | 1.65× |
| 11 | 241 | 0.181 | 0.110 | 1.64× |

For history: before the P3-08/P3-11 word-parallel optimizations the d=11 ratio

## 3. MPS backend: 128-qubit shallow circuit

Non-Clifford NN brickwork, n=128, 6 brick layers (CNOT·Rz·CNOT bricks
alternating even/odd bonds + Rx mixer walls), 2,039 gates; `MpsBackend` χ=64,
single-threaded.

| n | depth | χ | wall time (run) | truncation error | max bond reached |
|----:|------:|---:|----------------:|-----------------:|-----------------:|
| 128 | 6 | 64 | **10.3 ms** | 1.07e-13 | 8 |

The run is exact by a wide margin: brick parity alternation bounds the Schmidt
rank at 2³ = 8, so χ=64 never binds. Validated against an exact state-vector
reference computed on the backward light-cone subcircuit: ⟨Z_i⟩ and
⟨Z_i Z_{i+1}⟩ observables match to 1e-10. The demo runs as a CI guard
(`mps_128q_shallow_demo`), so the result cannot silently regress.

Source: `docs/perf/mps_100q.md`

## 4. Backend feature matrix

| backend | representation | capacity | exactness | use it for |
|---------|----------------|----------|-----------|------------|
| `sv` | dense 2ⁿ complex amplitudes | ≤ 28 qubits (default cap) | exact (FP64) | any circuit that fits in memory — the general-purpose workhorse |
| `mps` | matrix product state (bond dim χ) | 100+ qubits (1024 hard cap) for shallow/local circuits | exact while χ is not binding; controlled truncation otherwise | low-entanglement circuits: shallow brickwork, nearest-neighbour dynamics |
| `stab` | CHP tableau, O(n²) bits | hundreds of qubits (65,536 hard cap) | exact | Clifford-only circuits: error-correction cycles, stabilizer states |

## 5. Methodology

- **Single-thread both sides, pinned.** aleph with `RAYON_NUM_THREADS=1`, Aer
  with `max_parallel_threads=1` under `taskset`; Stim's `TableauSimulator` is
  single-threaded. This isolates per-core efficiency from parallel scaling.
- **Shared circuit corpus.** Both simulators consume the same transpiled
  OpenQASM files (`scripts/qiskit-baseline/circuits/`), so gate counts and
  decompositions are identical on each side.
- **Timing.** criterion (10 samples, RSD reported in the source tables) for
  sub-minute sizes; single-shot one-shot timer for the big runs (e.g. n=30
  state vectors, ~16 GiB).
- **CPU-optimization history.** The single-core kernel work behind these
  numbers is documented per phase: `docs/perf/phase0.md` (baseline),
  `docs/perf/phase1.md` (SIMD + IR passes, ≤2× Aer exit metric),
  `docs/perf/phase2.md` (multi-threaded scaling).

## 6. Honest caveats

- **Sycamore random circuits: aleph is 3.1–5.3× slower than single-thread
  Aer** (n20 5.21×, n24 5.26×, n28 3.70×, n30 3.08×). Sycamore has no
  diagonal/special-gate structure for aleph's fusion/diagonal passes to
  exploit, so it runs on the generic dense-1q + CZ kernels where Aer's C++
  wins single-thread; the ratio improves with n as per-amplitude work
  amortizes. (`docs/perf/phase4.md`)
- **Surface code: still slower than Stim at scale** — 1.64× at d=11 (241
  qubits). Stim is a purpose-built, heavily-optimised stabilizer simulator;
  its bit-packed CHP wins at scale. aleph is faster than Stim at d=3/5.
  (`docs/perf/surface_code.md`)
- **VQE ratios at n≤8 are overhead-bound, not kernel throughput.** The state
  is tiny (≤256 amplitudes), so the 0.01–0.04× ratios reflect aleph's lean
  pyo3→Rust per-call path vs Aer's Python-orchestrated per-call overhead —
  the dominant cost of the small-molecule VQE inner loop, but not a raw
  kernel comparison. (`docs/perf/phase4.md`)
- **QAOA MPS at n≤14 is slower than SV.** The state vector is tiny (≤16K
  amplitudes), so SV constant factors win; QAOA's entanglement growth makes
  MPS expensive at p≥2, and MPS's crossover is at larger n.
  (`docs/perf/qaoa.md`)
- **This report is single-thread.** Multi-threaded execution exists (Phase 2:
  rayon-parallel kernels, NUMA-aware allocation) but state-vector gate
  application is memory-bandwidth-bound, so parallel efficiency at 16 threads
  is well below ideal — see `docs/perf/phase2.md` for measured scaling.
