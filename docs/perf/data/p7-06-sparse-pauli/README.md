# P7-06 validation receipts

See [report](../../p7-06-sparse-pauli.md) for the API, exact numerical convention, supported scope, limits, measurement protocol and adverse cases.

The valid campaign compares the new sparse expectation API (with and without P7-03 cones), the existing FP64 `NaiveSvBackend`, `ExactExpectationQuery` on the small-cone overlap, and `MpsBackend` with bond cap 128 and no accepted recorded truncation above 1e-12. No full SV is attempted above 20 qubits. GHZ/product cases have analytic references; local128 has an independent compact-SV reference. Every retained timed/cold result is checked to 1e-10.

`receipts.tar.gz` contains all 430 forward/reverse paired observations,43 cold-process RSS runs, raw Criterion samples/estimates, compiler artifact metadata, source/binary hashes, build/test logs, load trajectories and the exact historical runner. `summary.json` and `criterion-estimates.json` expose the corresponding tables without unpacking. Timing/cold-RSS observations are not IID samples or hard resource guarantees. Public-API paired times include planning, allocation, execution, release and JSON-adapter bookkeeping; Criterion excludes the JSON adapter. Process RSS includes inputs, compiled plans, executable/runtime and allocator overhead; the engine's sparse workspace cap counts only its declared term/key payload.

The CPU host is shared: CPU 3 affinity, sibling 23 monitored, Rayon=1, no services or runners stopped. Preflight/load accounting is coarse and cannot exclude short interruptions, cache/frequency effects or prove isolation. All valid measurements are retained; no fastest-run selection or result-based retuning.

`source-sha256.json` identifies the tested functional source. `query.qasm`/`query.pauli` plus the two `aleph-548-query-*.json` files retain the public file-input smoke (Mac), expecting cos(.37)+.3. `local-release-tests.log` and `beta-workspace-clippy.log` record local checks. Linux suite receipts are inside the valid archive. Only existing workspace crates were added as dev dependencies; the library adds no dependency or unsafe code.

`run.py`, `summarize.py`, and `plot.py` reproduce the campaign analysis/figure. Historical runner paths refer to the isolated `/tmp/aleph-548-f6a7808` experiment. Use the report's example/bench commands for a new environment; timing results will differ.

`mtime-cache-audit.tar.gz` is **INVALID/EXCLUDED** provenance evidence, not another valid result set. Source updates extracted from tar preserved mtimes older than an earlier benchmark build. Cargo reported `fresh:true`, reusing that benchmark executable after source content changed. A timing discrepancy between release and Criterion led to the discovery. The first capture is preserved in full and excluded regardless of performance. A default-profile clean removed no release files; the freshness guard blocked measurement. A subsequent guard also blocked an example already freshly built by `cargo test`. The final runner cleans the explicit release profile, refreshes already-hash-verified source mtimes, explicitly builds example/bench before tests, and requires **fresh=false for both executable and aleph_stab library artifacts** in each profile before the single valid recapture. This is source/binary validation, not selection for better timings.
