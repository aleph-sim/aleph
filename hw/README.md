# `hw/` — sim-first FPGA decoder track (Phase Q6)

The North Star of the QEC track is a real-time decoder on hardware (FPGA → ASIC). The board (a
**Xilinx Kria KV260**) is being procured; this directory starts the work **in simulation** so the
RTL, testbench, and host↔hardware data flow are ready and verified before the board arrives.
Simulation is Mac-native (Verilator); synthesis (Vivado) targets the KV260 and runs on an x86 Linux
box later.

## What's here (Q6-01, sim)

A distance-3 rotated surface-code memory-Z decoder as synthesisable RTL, verified in simulation:

| file | role |
|------|------|
| `surface_d3_decoder.sv` | the decoder: an 8-bit syndrome indexes a 256-entry ROM → 1-bit logical correction, with a 1-cycle valid/valid handshake (the "syndrome-in / correction-out skeleton"). |
| `surface_d3_lut.mem` | the ROM contents — **generated by the Rust Union-Find decoder** (`crates/aleph-qec/examples/qec_d3_lut_table.rs`), so the hardware reproduces a real decoder, not a toy. |
| `tb_surface_d3.cpp` | Verilator testbench: drives all 2^8 syndromes, checks the RTL against the Rust oracle, and reports decode latency. |
| `Makefile` | regenerate the LUT, build with Verilator, run. |

## Run it

```bash
brew install verilator        # one-time (macOS)
cd hw && make                 # regenerate LUT + build + run the testbench
```

Expected: `PASS: 256/256 syndromes match oracle; decode latency = 1 clock(s)`.

## Why a lookup table (and why that's OK here)

A full syndrome→correction table is exponential in the detector count, so LUTs do **not** scale past
tiny codes. The point of Q6-01 is the *flow*, not the algorithm: prove that a Rust-derived decoder
can be turned into RTL and verified bit-exactly in simulation, with a clean streaming interface and a
measured per-decode latency. The real, scalable datapath — a **Union-Find** decoder (the algorithm
chosen for hardware: low, bounded latency) — is **Q6-02**, and it slots behind the same interface.

## Roadmap

- **Q6-01 (this):** sim-first toolchain + d=3 LUT decoder skeleton, Verilator-verified vs the Rust
  decoder. ✅ (sim)
- **Q6-02:** Union-Find decoder datapath in RTL; cycle-accurate latency in Verilator; then synthesise
  for the KV260 and measure on-board latency.
- **Q6-03:** GPU (Q3-01) vs FPGA latency/throughput/power report.

The board self-programs from its on-board ARM Linux; Vivado (x86-Linux only) builds the bitstream.
